# 使用AI编写UI自动化脚本并自动执行的最佳实践方案

针对“使用 AI 编写 UI 自动化脚本并自动执行”这一目标，基于前两轮讨论，当前**最佳实践方案**可以概括为：

> **以工程化框架为骨架，AI 作为智能“润滑剂”与“自愈引擎”的混合模式。**

具体由以下四个核心层构成：

---

## 一、页面与元素的工程化管理（骨架层）

**目标**：让 80% 以上的常规操作走确定性路径，避免 AI 的高成本与不确定性。

| 组件                                | 做法                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| **AI 增强的页面对象模型（AI-POM）** | 用 AI 辅助生成初始 POM（含元素定位器、操作函数），存入代码仓库，版本可控。运行时优先调用 POM 方法。 |
| **语义快照缓存**                    | 将页面可访问性树（AX Tree）或简化 DOM 结构化存储。比对版本差异，无变化时直接复用定位策略，不调用 AI。 |
| **组件模板库**                      | 为通用组件（日期选择器、分页、模态框）预置操作模板，AI 仅需识别组件类型，调用模板执行。 |
| **流程编排 DSL / 状态机**           | 复杂业务流程用工程化方式定义（如 YAML 工作流），AI 只负责处理步骤内的动态决策，不接管流程控制。 |

---

## 二、AI 的有限角色（智能层）

**目标**：AI 只在以下三种场景被激活，其他时刻“静默”。

| 场景             | AI 职责                                                      |
| ---------------- | ------------------------------------------------------------ |
| **初始脚本生成** | 给定自然语言用例或人工操作录屏，AI 生成初步脚本 + POM 建议，人工审核后入库。 |
| **运行时自愈**   | 当工程化定位失败时（如元素找不到、超时），AI 通过视觉/语义分析重新定位，并返回新选择器。 |
| **未知异常处理** | 遇到未在经验库登记的异常页面（如新样式弹窗、A/B 测试布局），AI 探索解决方案，成功后**自动沉淀为经验**。 |

**注意**：AI 默认不参与正常路径执行，以避免延迟和成本。

---

## 三、经验沉淀与闭环（进化层）

**目标**：让每次 AI 的“思考”都变成可复用的资产，避免重复踩坑。

| 沉淀形式           | 说明                                                         |
| ------------------ | ------------------------------------------------------------ |
| **自我修复库**     | 记录 `(页面特征, 失败定位器, AI 新定位器)` 映射。下次相同元素找不到时，直接命中修复，无需再调 AI。 |
| **异常模式库**     | 结构化存储异常类型（验证码、会话超时、网络中断、弹窗等）及其对应的处理策略（调用打码平台、刷新重试、关闭弹窗模板等）。 |
| **失败案例知识库** | 以向量数据库存储历史失败页面截图 + 错误描述 + 最终解决方案。新异常先做相似性检索。 |
| **定期模型微调**   | 积累足够多的“页面-DOM-正确操作”数据后，对本地小模型（如 7B 参数）进行微调，降低对外部大模型的依赖。 |

---

## 四、执行引擎与监控（运行层）

**目标**：保证脚本执行的可靠性、可观测性、可回滚。

| 功能           | 实现方式                                                     |
| -------------- | ------------------------------------------------------------ |
| **混合执行器** | 优先执行 POM 确定动作，捕获异常后进入“自愈流程”（查经验库 → 查 AI → 沉淀）。 |
| **运行看板**   | 记录每次执行的步骤、耗时、是否触发 AI、自愈成功率、成本（API 调用次数）。 |
| **版本回滚**   | POM 和脚本版本与代码仓库绑定，发现 AI 产生错误修复时可一键回退。 |
| **安全围栏**   | 对 AI 可能产生危险操作（如删除数据、点击支付）设置人工确认或只读模式。 |

---

## 总结一句话的最佳方案

> **构建“AI 辅助生成 + 工程化 POM 执行 + 经验库驱动自愈 + 有限 AI 兜底”的四层架构，其中 AI 只用于初始脚本生成、定位失败时的动态修复、以及未知异常的探索沉淀，其余所有确定性路径和异常模式复用工程化资产。**

这个方案兼顾了：
- ✅ **稳定性**（确定性路径毫秒级执行，不出错）
- ✅ **抗变化能力**（页面改版时 AI 自愈，同时更新 POM）
- ✅ **低成本**（90% 执行不调用大模型）
- ✅ **可维护性**（经验库让 AI 越用越聪明）

目前业界领先的开源实践（如 **Midscene.js + 自愈库**、**Browser Use + 经验回放**）以及企业级商业工具（如 **Applitools + Visual AI**、**Mabl**）本质上都是这个思路。
