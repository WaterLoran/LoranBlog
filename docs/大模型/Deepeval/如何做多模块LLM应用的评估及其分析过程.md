# 如何做多模块LLM应用的评估及其分析过程

对于多模态 LLM 应用（图像生成、图文理解、视频分析等）的评估，其核心难点在于**跨模态对齐**（文本与图像是否匹配）以及**主观质量**（图像是否美观、有用）。决定评估哪些指标，需要根据**任务类型、模态组合、用户预期**进行系统分析。

下面提供一个**多模态评估的六步决策框架**，帮助你根据实际情况精准选择评估项。

---

## 多模态评估决策框架（六步法）

### 第一步：明确任务类型与模态组合

多模态应用有多种形式，每种形式的评估重点完全不同。

| 任务类型         | 输入          | 输出         | 典型场景           | 核心评估维度                 |
| :--------------- | :------------ | :----------- | :----------------- | :--------------------------- |
| **文本生成图像** | 文本描述      | 图像         | DALL·E、Midjourney | 图文一致性、图像质量、美学   |
| **图像生成文本** | 图像          | 文本描述     | 图像字幕、VQA      | 描述准确性、相关性、细节覆盖 |
| **图像编辑**     | 图像+文本指令 | 修改后的图像 | “把背景换成海滩”   | 编辑忠实度、原图保留度       |
| **图文问答**     | 图像+文本问题 | 文本答案     | 识别图表、分析场景 | 答案正确性、视觉推理能力     |
| **视频理解**     | 视频+问题     | 文本/动作    | 监控分析、视频检索 | 时序一致性、事件检测         |
| **多模态对话**   | 图像+多轮文本 | 文本+图像    | 设计助手、教学     | 多轮记忆、跨模态一致性       |

**分析问题**：你的应用属于上述哪一类？输入和输出分别包含哪些模态？

**输出**：确定任务类型，从而锁定候选指标组。

---

### 第二步：识别关键质量维度

对于多模态任务，质量不是单一维度，而是多个维度的平衡。你需要根据业务目标为每个维度分配权重。

| 维度           | 定义                                         | 适用任务           | 对应 DeepEval 指标                 |
| :------------- | :------------------------------------------- | :----------------- | :--------------------------------- |
| **图文一致性** | 生成图像是否准确反映文本描述的所有细节       | 文本→图像          | `ImageCoherence`                   |
| **图像质量**   | 清晰度、色彩、噪声、伪影                     | 任何生成图像的任务 | 可集成外部IQA模型（如CLIP-IQA）    |
| **编辑忠实度** | 编辑指令是否被准确执行，无关部分是否保持不变 | 图像编辑           | `ImageEditing`                     |
| **描述准确性** | 生成的文本是否完整、正确描述图像内容         | 图像→文本          | `TextToImage`（反向）或自定义      |
| **视觉推理**   | 是否理解图像中的空间关系、数量、属性         | VQA                | `ImageHelpfulness`（问题解决程度） |
| **时序一致性** | 视频/多帧生成中，前后帧是否连贯              | 视频生成           | 需自定义（如帧间相似度）           |

**分析问题**：用户最在意“像不像”（一致性）还是“好不好看”（质量）？如果是工具性用途（如设计稿生成），一致性权重大于美观；如果是艺术创作，美观权重更高。

**输出**：列出 2-4 个核心维度，并排序优先级。

---

### 第三步：收集典型失败模式（基于真实用例）

通过人工检查或用户反馈，找出最常见的多模态错误。

| 失败模式                     | 示例                                         | 对应指标                   |
| :--------------------------- | :------------------------------------------- | :------------------------- |
| **文本描述中的对象遗漏**     | 提示词“一只戴红帽子的白猫”，生成的猫没戴帽子 | `ImageCoherence`           |
| **属性错误**                 | “红色汽车”生成了蓝色汽车                     | `ImageCoherence`（细粒度） |
| **图像伪影/畸形**            | 手指数量错误、文字乱码                       | 图像质量指标               |
| **编辑时改变了不该改的部分** | 只要求换背景，结果人物衣服也变了             | `ImageEditing`             |
| **图像描述不完整**           | 描述一张有3个人的图，只说了“有人”            | 自定义完整性指标           |
| **对图像中的文字识别错误**   | 路牌上的“STOP”识别成“GO”                     | 自定义OCR准确率            |

**方法**：抽取 50-100 个生成样本，人工标注错误类型，统计各类占比。占比最高的 1-2 类就是首要评估目标。

**输出**：确定最需优先解决的失败模式。

---

### 第四步：评估资源与可行性

多模态评估通常比纯文本更昂贵，因为需要额外的视觉模型或人工标注。

| 资源需求          | 说明                                           | 对指标选择的影响                                             |
| :---------------- | :--------------------------------------------- | :----------------------------------------------------------- |
| **参考图像/描述** | 某些指标需要“标准答案”（如期望输出图像或字幕） | 如果没有，只能选无参考指标（如`ImageCoherence`通过CLIP计算图文相似度） |
| **视觉模型**      | DeepEval 多模态指标底层依赖 CLIP、BLIP 等模型  | 这些模型会额外占用内存和计算时间                             |
| **人工评估**      | 美学、主观满意度难以自动化                     | 如果预算有限，可先依赖自动指标，再抽样人工复核               |
| **测试集规模**    | 多模态测试集通常较小（因标注成本高）           | 优先选择不需要标注的指标，或使用合成数据                     |

**DeepEval 多模态指标的开箱可用性**：
- `ImageCoherence`：无需参考，基于 CLIP 计算图文相似度 ✅
- `ImageHelpfulness`：需要用户问题，评估图像对回答的帮助程度 ✅
- `TextToImage`：需要期望图像（参考）⚠️
- `ImageEditing`：需要原始图像、编辑指令、期望结果图像 ⚠️

**输出**：筛选出在当前资源下可行的指标集合。

---

### 第五步：对齐业务目标与用户体验

除了技术正确性，多模态应用还需要考虑业务价值和主观体验。

| 业务目标           | 可选的评估方式                            | 适用场景               |
| :----------------- | :---------------------------------------- | :--------------------- |
| **用户任务完成率** | 用户是否基于生成的图像做出了正确决策      | 设计工具、医学影像分析 |
| **生成速度**       | 记录生成图像的耗时                        | 实时交互应用           |
| **用户满意度**     | A/B 测试、用户评分                        | 内容创作平台           |
| **安全性**         | 检测生成图像是否包含 NSFW、暴力、偏见内容 | 公开服务               |

**输出**：决定是否需要加入业务指标（如任务完成率）或安全指标。

---

### 第六步：设计分层评估策略

多模态评估也可以分层，从快速自动指标到深度人工评估。

```
        /\
       /  \  少量：端到端用户体验（人工评估 + A/B测试）
      /____\
     /      \ 中等：核心质量维度（图文一致性、编辑忠实度）
    /________\
   /          \ 大量：基础格式/安全检查（是否生成空图、是否违规）
```

**示例分层**（文本生成图像应用）：

| 层级            | 内容                             | 指标/方法                      | 运行频率   |
| :-------------- | :------------------------------- | :----------------------------- | :--------- |
| **L1 冒烟**     | 是否成功生成图像（非空、非报错） | 自定义（检查输出格式）         | 每次提交   |
| **L2 自动评估** | 图文一致性、图像质量（CLIP分数） | `ImageCoherence` + CLIP-IQA    | 每日构建   |
| **L3 核心维度** | 编辑忠实度（如果有编辑任务）     | `ImageEditing`（需标注测试集） | 每周       |
| **L4 人工评估** | 美学、用户满意度                 | 抽样人工评分                   | 每次发版前 |

## 实际案例：电商商品背景替换工具

**场景**：用户上传商品照片（如鞋子），输入文本“把背景换成海滩”，系统生成编辑后的图像。用于电商平台展示。

### 应用六步法：

1. **任务类型**：图像编辑（输入：原图+文本指令；输出：新图像）
2. **核心维度**：编辑忠实度（背景是否成功替换）、原图保留度（鞋子外观不变）、图像真实性（边缘是否自然）
3. **失败模式**：最常见的是鞋子颜色改变、背景替换不完整、合成边缘生硬
4. **可行性**：有原图和编辑指令，但没有“期望结果图”。可以使用 `ImageEditing` 指标，它需要原图+编辑指令+生成图，但不强制需要参考图（通过CLIP评估指令遵循度）。另外可自定义背景分割准确率。
5. **业务目标**：用户最终是否使用该图像（点击“应用”按钮） → 任务完成率
6. **分层策略**：
   - L1：生成图像尺寸是否正确、是否包含明显伪影（基于规则）
   - L2：`ImageEditing` 评估指令遵循度；自定义背景分割 IoU（如果有掩码标注）
   - L3：人工评估 50 张图像的整体自然度

**最终选择的指标**：
- **必选**：`ImageEditing`（用 CLIP 评估背景是否变成海滩）
- **强烈推荐**：自定义 `PreservationScore`（与原图在非编辑区域的像素相似度）
- **可选**：`ImageHelpfulness`（模拟用户问“这双鞋适合海滩吗”，看生成图是否能帮助回答）
- **暂缓**：`TextToImage`（因为没有期望图像）

## 总结：决策流程图

```
开始
 │
 ▼
【确定任务类型】文本→图像 / 图像→文本 / 编辑 / VQA / 视频
 │
 ▼
【识别质量维度】一致性、质量、忠实度、准确性、时序等 ──► 候选指标
 │
 ▼
【收集失败模式】人工分析生成样本 ──► 锁定优先指标
 │
 ▼
【评估可行性】有无参考图像？有无视觉模型资源？ ──► 筛选可落地指标
 │
 ▼
【对齐业务目标】任务完成率？满意度？安全？ ──► 补充指标
 │
 ▼
【分层设计】L1冒烟 → L2自动 → L3核心 → L4人工
 │
 ▼
输出：指标清单 + 测试集 + 运行频率 + 人工抽检比例
```

**关键原则**：多模态评估**从无参考指标起步**（如 `ImageCoherence` 基于 CLIP），因为它们不需要人工标注。然后逐步引入需要参考图像的指标（如 `TextToImage`），并配合人工抽样评估主观质量。如果资源允许，可以构建一个小型标注测试集（例如 200 个图文对）来更精确地评估一致性。
