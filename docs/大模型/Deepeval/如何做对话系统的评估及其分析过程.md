# 如何做对话系统的评估及其分析过程

对于对话系统（Chatbot / Conversational AI）的评估，其核心难点在于**多轮交互中的状态跟踪、一致性、以及长期记忆**。决定评估哪些指标，需要从**对话类型、用户目标、典型失败模式**三个维度进行系统分析。

下面提供一个**对话系统评估的六步决策框架**，帮助你根据实际情况精准选择评估项。

---

## 对话系统评估决策框架（六步法）

### 第零步：明确对话系统的类型（最关键）

不同类型对话系统的“成败”定义完全不同。先给自己系统归类：

| 类型       | 典型场景           | 核心成功标准             | 失败代价               |
| :--------- | :----------------- | :----------------------- | :--------------------- |
| **任务型** | 订票、客服、IT支持 | 高效、准确完成任务       | 任务失败、用户反复确认 |
| **闲聊型** | 情感陪伴、娱乐     | 有趣、自然、不冷场       | 无聊、重复、脱离人格   |
| **问答型** | FAQ、知识库问答    | 每轮答案正确、不重复提问 | 答非所问、遗漏信息     |
| **混合型** | 智能助手（如Siri） | 兼顾任务与闲聊           | 上述所有问题的组合     |

**输出**：确定主类型，后续指标选择将以此为基础。

---

### 第一步：识别对话生命周期中的关键节点

对话不是单轮，而是多轮状态流转。每个节点都可能出错：

```
用户第一轮 ──► 系统回复 ──► 用户第二轮（可能引用历史）──► 系统回复 ──► ...
   │              │                │                          │
   ▼              ▼                ▼                          ▼
意图识别      响应相关       上下文理解                一致性/记忆
```

| 节点               | 失败表现                                     | 对应评估指标                          |
| :----------------- | :------------------------------------------- | :------------------------------------ |
| **首轮意图理解**   | 第一轮就误解用户                             | `ConversationRelevancy`（整体相关性） |
| **多轮上下文追踪** | 忘记用户刚才提到的关键信息                   | `KnowledgeRetention`                  |
| **角色一致性**     | 客服机器人突然说“我是AI，不是真人”           | `RoleAdherence`                       |
| **回复不重复**     | 同样的问题问两遍，给出不同或矛盾的答案       | `Consistency`                         |
| **对话自然结束**   | 用户问题已解决但机器人还在啰嗦               | `ConversationCompleteness`            |
| **避免无效回复**   | 用户说“谢谢”，机器人还在问“还有什么可以帮您” | `Politeness` + 自定义结束检测         |

**分析问题**：在你的系统线上日志中，用户放弃对话或给出差评通常发生在哪个节点？那里就是你的评估重点。

---

### 第二步：收集用户真实对话样本，标注失败类型

抽取 100-200 条完整对话（尤其是用户主动中断或给差评的对话），人工标注失败原因。常见分类：

| 失败类别               | 占比示例 | 优先评估指标               |
| :--------------------- | :------- | :------------------------- |
| 系统忘记前文信息       | 30%      | `KnowledgeRetention`       |
| 回复与当前话题无关     | 25%      | `ConversationRelevancy`    |
| 角色前后矛盾           | 15%      | `RoleAdherence`            |
| 任务未完成就结束       | 15%      | `ConversationCompleteness` |
| 回复内容重复           | 10%      | 自定义重复度指标           |
| 其他（不礼貌、太长等） | 5%       | `Politeness` 等            |

**输出**：选择占比最高的 1-3 类作为核心评估目标。

---

### 第三步：对齐业务指标（非功能性需求）

即使对话技术上正确，业务可能还关心效率、成本和用户体验。

| 业务关切         | 可选的评估方式                                   | 说明                                   |
| :--------------- | :----------------------------------------------- | :------------------------------------- |
| **任务解决率**   | 人工评估或 `TaskCompletion`（需定义任务边界）    | 最贴近业务价值                         |
| **平均交互轮数** | 非DeepEval直接指标，但可统计                     | 轮数过少可能问题没解决，过多可能效率低 |
| **用户满意度**   | 使用 `UserSatisfaction` 指标（需代理模型或人工） | 适合闲聊型                             |
| **知识库利用率** | 统计是否频繁需要人工介入                         | 可作为评估上下文                       |
| **成本**         | token 数、API 调用次数                           | 对话越长成本越高                       |

**输出**：决定是否需要加入 `TaskCompletion` 或 `UserSatisfaction` 等高级指标。

---

### 第四步：评估资源与可行性

对话系统的评估通常比单轮更昂贵，因为需要模拟多轮交互和状态。

| 资源限制                   | 影响                                                         |
| :------------------------- | :----------------------------------------------------------- |
| **是否有标注的完整对话？** | 如果没有，可以用 `Synthesizer` 生成多轮对话测试集            |
| **评估成本**               | 每轮对话可能需要多次调用 LLM 作为评判员，费用线性增长        |
| **自动化程度**             | `RoleAdherence`、`KnowledgeRetention` 可自动；`TaskCompletion` 可能需要人工确认最终状态 |
| **测试用例设计**           | 需要设计对话脚本（用户模拟器）或预设多轮输入                 |

**策略建议**：
- **初始阶段**：只用 `ConversationRelevancy` + `KnowledgeRetention`（只需对话历史，无需标注）
- **有标注资源后**：增加 `RoleAdherence`、`Consistency`
- **有任务定义后**：增加 `TaskCompletion`（需要定义成功标准）

---

### 第五步：设计分层评估策略

对话系统的评估不宜“一刀切”，应采用**多层级测试金字塔**：

```
        /\
       /  \  少数：完整任务成功（端到端对话模拟）
      /____\
     /      \ 中等：关键子能力（记忆、角色、不重复）
    /________\
   /          \ 大量：单轮基础（相关性、安全、格式）
  /____________\
```

**示例分层**（客服对话系统）：

| 层级            | 评估内容               | 指标                                          | 运行频率     |
| :-------------- | :--------------------- | :-------------------------------------------- | :----------- |
| **L1 单轮回归** | 每轮回复是否相关、安全 | `AnswerRelevancy`（拆成单轮）、`Toxicity`     | 每次提交     |
| **L2 多轮能力** | 记忆前文、角色一致     | `KnowledgeRetention`, `RoleAdherence`         | 每日构建     |
| **L3 完整对话** | 任务是否成功解决       | `TaskCompletion`（模拟用户与系统对话 3-5 轮） | 每周或发版前 |

## 实际案例：银行客服对话系统

**场景**：用户询问“我的信用卡账单是多少”，然后可能追问“那最低还款额呢”，或者“上个月的消费明细”。系统需要记住当前讨论的是哪张卡、哪个时间范围。

### 应用六步法：

1. **类型**：任务型（账单查询、还款）
2. **关键节点**：多轮上下文追踪最易出错（用户不说“还是刚才那张卡”，系统应默认记住）
3. **用户抱怨**：最常见的是“我刚刚说了卡号，它又问一遍” → `KnowledgeRetention` 差
4. **业务指标**：任务完成率（最终是否成功展示账单）
5. **可行性**：可设计标准对话脚本（用户问“查询账单”→系统问卡号→用户提供→系统展示），自动检查中间步骤是否重复提问
6. **分层策略**：
   - L1：单轮回答是否包含敏感信息（`PIILeakage`）
   - L2：是否记住上一轮提到的卡号（自定义 `KnowledgeRetention` 测试）
   - L3：完整 3 轮对话后，是否给出正确的账单数据（`TaskCompletion`）

**最终选择的指标**：
- **必选**：`KnowledgeRetention`, `RoleAdherence`（保持客服身份）
- **可选**：`ConversationCompleteness`（检测是否提前结束对话）
- **暂缓**：`UserSatisfaction`（人工成本高，先看任务完成率）

## 总结：决策流程图

```
开始
 │
 ▼
【确定对话类型】任务型/闲聊型/混合型
 │
 ▼
【拆解生命周期】哪个节点最容易出错？
 │
 ▼
【分析真实日志】高频失败分类 ──► 锁定 1-3 个核心指标
 │
 ▼
【对齐业务目标】任务完成率？满意度？效率？
 │
 ▼
【评估可行性】有无多轮测试数据？成本可接受？
 │
 ▼
【分层设计】单轮回归 → 多轮能力 → 完整任务
 │
 ▼
输出：指标清单 + 测试集规模 + 运行频率
```

**关键原则**：对话系统的评估**从单轮基础指标起步**（如 `AnswerRelevancy`），然后逐步加入多轮能力指标（`KnowledgeRetention`、`RoleAdherence`），最后才投入成本较高的完整任务模拟（`TaskCompletion`）。不要一开始就追求完美模拟，先用最简单的自动化指标捕捉大部分回归问题。
