# DeepEval 全指标详解

## DeepEval 全指标详解（分类+说明+场景）

DeepEval 提供了 **50+ 开箱即用的评估指标**，覆盖了 LLM 应用的主要场景。所有指标均输出 **0~1 之间的分数**（越高越好），并可附带详细的评分理由。

> 💡 **指标通用属性**：每个指标都支持 `threshold`（阈值，默认 0.5）和 `model`（指定评判用的 LLM）。分数 ≥ threshold 表示测试通过 ✅。

---

## 一、RAG 系统评估指标（最常用）

| 指标名称                | 说明                                         | 工作原理                                                     | 适用场景                                               |
| :---------------------- | :------------------------------------------- | :----------------------------------------------------------- | :----------------------------------------------------- |
| **AnswerRelevancy**     | 答案与用户问题的相关程度。                   | 让 LLM 生成几个与答案相关的问题，再与原始问题计算语义相似度。分数越低说明答非所问。 | 任何 RAG 或 QA 系统，防止“跑题”。                      |
| **Faithfulness**        | 答案是否严格基于给定的上下文（防幻觉）。     | 将答案拆成若干断言，逐一检查是否可以从上下文中推理得出。     | 要求答案可溯源的场景（医疗、法律、客服）。             |
| **ContextualRecall**    | 期望答案中的关键信息是否都被检索到了。       | 将期望答案拆成若干断言，检查每个断言是否被检索上下文覆盖。   | 评估检索器是否漏掉了重要信息。需要 `expected_output`。 |
| **ContextualPrecision** | 检索结果中相关文档的排序质量。               | 检查每个检索到的文档块，评估其是否真正有助于回答用户问题，并按顺序加权计算。 | 需要优化检索排序的场景。需要标注每个文档块是否相关。   |
| **ContextualRelevancy** | 检索到的上下文与用户问题的相关程度（整体）。 | 判断每个检索块是否与问题相关，计算相关块的比例。             | 评估检索是否引入了大量噪音。无需参考答案。             |
| **KnowledgeRetention**  | 模型在对话中是否记住了之前提到的知识。       | 模拟多轮对话，在后续轮次提问之前提及的信息，检查模型能否正确回忆。 | 客服机器人、个人助理等需要长期记忆的场景。             |

### 🔧 特殊 RAG 指标（高级）
- `AnswerSimilarity`：基于 BERTScore 计算答案与期望答案的语义相似度（需参考答案）。
- `Correctness`（GEval 定制）：通过自然语言标准评估答案的整体正确性。
- `Hallucination`：通用幻觉检测（不依赖上下文，模型自身知识导致的编造）。

## 二、智能体（Agent）评估指标

| 指标名称                 | 说明                                                    | 适用场景                                                     |
| :----------------------- | :------------------------------------------------------ | :----------------------------------------------------------- |
| **TaskCompletion**       | 智能体是否成功完成用户指定的最终任务。                  | 评估任何有明确目标的 Agent（如订票、数据分析）。需要定义“任务成功”标准（可基于最终输出或工具调用序列）。 |
| **ToolCorrectness**      | 智能体调用的工具、参数、时机是否正确。                  | 检查每次工具调用的名称、参数值是否与期望完全匹配。           |
| **GoalAccuracy**         | 智能体的子目标和中间步骤是否始终朝着最终目标前进。      | 多步骤规划型 Agent，防止中途跑偏。                           |
| **PlanAdherence**        | 智能体是否遵循了预设的计划或思维链。                    | 需要先定义期望的计划步骤（例如先搜索，再计算，最后回答）。   |
| **StepEfficiency**       | 完成任务所需的步骤是否最少（或低于某个阈值）。          | 对成本或延迟敏感的应用，鼓励简洁的规划。                     |
| **Coherence**            | 智能体的思考过程和最终输出是否连贯、逻辑一致。          | 通用质量评估，尤其适合思维链展示的场景。                     |
| **UserSatisfaction**     | 模拟用户对智能体回答的满意程度（用 LLM 作为代理用户）。 | 难以定义精确成功标准时，使用大模型打分。                     |
| **ExecutionReliability** | 智能体执行代码或命令时是否无错误、无异常。              | 代码生成、RPA 类 Agent。                                     |

> 注意：部分 Agent 指标（如 `TaskCompletion`）需要配合 `expected_tool_calls` 或 `expected_final_answer` 使用。

## 三、对话系统评估指标（多轮）

| 指标名称                     | 说明                                                         | 适用场景                                               |
| :--------------------------- | :----------------------------------------------------------- | :----------------------------------------------------- |
| **ConversationRelevancy**    | 每一轮回复是否都与当前对话话题相关，没有跑题。               | 通用对话机器人，防止答非所问。                         |
| **KnowledgeRetention**       | 同上（RAG 部分已介绍），在多轮中检查记忆。                   | 需要记住用户之前信息的场景（如用户告知了姓名、偏好）。 |
| **RoleAdherence**            | 模型是否始终遵循预设的角色设定（如客服、医生、朋友）。       | 对角色扮演有严格要求的场景。需要提供 `system_prompt`。 |
| **ConversationCompleteness** | 对话是否覆盖了所有必要的信息或步骤（例如客服流程中询问了所有必要细节）。 | 任务型对话，确保流程不遗漏。需要定义“完整”的标准。     |
| **Consistency**              | 模型在同一对话中的不同轮次对相同问题是否给出矛盾的回答。     | 避免前后矛盾，增强可信度。                             |
| **Politeness**               | 模型的回复是否礼貌、尊重用户。                               | 公开服务、客服场景。                                   |
| **NonRepetitiveness**        | 模型是否避免重复相同的短语或句子。                           | 提升对话自然度，避免用户厌烦。                         |

## 四、安全与合规评估指标

| 指标名称            | 说明                                                         | 适用场景                                            |
| :------------------ | :----------------------------------------------------------- | :-------------------------------------------------- |
| **PIILeakage**      | 检测输出是否包含个人隐私信息（邮箱、电话、身份证、IP 地址等）。 | 任何涉及用户数据的场景，特别是 GDPR/CCPA 合规要求。 |
| **Toxicity**        | 检测仇恨、侮辱、暴力、骚扰等有毒内容。                       | 公开对话、社交媒体、儿童产品。                      |
| **Bias**            | 检测针对性别、种族、宗教等属性的刻板印象或歧视性陈述。       | 招聘、金融、医疗等对公平性要求高的领域。            |
| **Misuse**          | 检测模型是否被用于恶意目的（如生成攻击性代码、武器制造方法、自杀指导等）。 | 防止滥用，符合法律和伦理要求。需要预设危险类别。    |
| **NonAdvice**       | 检测模型是否在未声明的情况下提供了医疗、法律、金融等专业建议。 | 专业领域助手，要求模型明确表示“非专业意见”。        |
| **PromptInjection** | 检测用户输入是否试图绕过系统指令（如“忽略之前的指令”）。     | 安全防护，尤其在面向公众的 API 中。                 |

## 五、多模态评估指标

| 指标名称                   | 说明                                                         | 适用场景                                 |
| :------------------------- | :----------------------------------------------------------- | :--------------------------------------- |
| **ImageCoherence**         | 生成的图像与文本描述之间的一致性。基于 CLIP 计算图文相似度。 | 文生图模型（DALL·E、Stable Diffusion）。 |
| **ImageHelpfulness**       | 生成的图像对回答用户问题的帮助程度。                         | 视觉问答（VQA），或图文结合的助手。      |
| **TextToImage**            | 评估从文本生成图像的整体质量，需要参考图像。                 | 有标准图像对比的场景。                   |
| **ImageEditing**           | 评估根据指令编辑图像的效果（忠实度、原图保留度）。           | 图像编辑工具。                           |
| **VideoTemporalCoherence** | 视频生成中相邻帧之间的连贯性（需自定义实现，DeepEval 提供基类）。 | 视频生成、帧插值。                       |

> 多模态指标依赖额外的视觉模型（如 CLIP），使用前需安装 `torch` 和 `transformers`。

## 六、通用/其他指标

| 指标名称            | 说明                                                         | 适用场景                                       |
| :------------------ | :----------------------------------------------------------- | :--------------------------------------------- |
| **GEval**           | 通过自然语言描述自定义评估标准，让 LLM 打分。                | 任何无法用现有指标覆盖的复杂质量要求。         |
| **DAG**             | 用有向无环图组合多个确定性规则（如格式检查、关键词匹配）来打分。 | 需要完全可控、无 LLM 调用的评估。              |
| **Summarization**   | 评估摘要的完整性、一致性、简洁性（内置三个子维度）。         | 文本摘要任务。                                 |
| **JSONCorrectness** | 检查输出是否为合法 JSON，并验证指定字段是否存在。            | 要求结构化输出的应用（如函数调用、数据抽取）。 |

## 七、如何选择合适的指标？

**决策速查表**：

| 你的应用类型      | 必选指标                                                     | 可选指标                                     |
| :---------------- | :----------------------------------------------------------- | :------------------------------------------- |
| 简单 QA（无检索） | `AnswerRelevancy`、`Hallucination`                           | `GEval`（自定义正确性）                      |
| RAG 知识库问答    | `Faithfulness`、`AnswerRelevancy`、`ContextualRecall`        | `ContextualPrecision`、`ContextualRelevancy` |
| 客服对话机器人    | `ConversationRelevancy`、`KnowledgeRetention`、`RoleAdherence` | `TaskCompletion`、`Politeness`               |
| 函数调用 Agent    | `ToolCorrectness`、`TaskCompletion`                          | `StepEfficiency`、`PlanAdherence`            |
| 内容审核过滤器    | `Toxicity`、`PIILeakage`、`Misuse`                           | `Bias`、`NonAdvice`                          |
| 文生图应用        | `ImageCoherence`                                             | `ImageEditing`、人工评估美学                 |

## 八、使用提示

- **无标注数据起步**：从 `AnswerRelevancy` + `Faithfulness`（RAG）或 `ConversationRelevancy`（对话）开始，这些指标只需要问题和模型输出。
- **逐步增加**：当你发现某种失败模式（如记忆差、工具调用错）后，再引入对应的专项指标。
- **阈值设定**：安全类指标建议设高阈值（0.9+），通用质量指标可设 0.5~0.7。
- **自定义指标**：如果内置指标不满足，使用 `GEval` 或继承 `BaseMetric` 自己实现。
