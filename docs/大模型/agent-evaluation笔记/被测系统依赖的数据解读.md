# 被测系统依赖的数据解读

下面按「`load_data` / `datas` 是什么 → 三个顶层键各自结构 → 和工具、任务里的 id 怎么对上」说明。

---

## 1. `load_data()` 和 `datas` 的关系

`data/__init__.py` 里的 `load_data()` 会读三个 JSON，拼成一个 **Python 字典** 返回：

```9:22:data/__init__.py
def load_data() -> dict[str, Any]:
    file_mapping = [
        ("orders", "orders.json"),
        ("products", "products.json"),
        ("users", "users.json")
    ]
    
    result = {}
    for key, filename in file_mapping:
        with open(os.path.join(FOLDER_PATH, filename)) as f:
            # 使用 object_pairs_hook=OrderedDict 保证JSON对象内部的键顺序
            result[key] = json.load(f, object_pairs_hook=OrderedDict)
    
    return result
```

也就是说，内存里结构是：

```text
{
  "orders":   <orders.json 的根对象>,
  "products": <products.json 的根对象>,
  "users":    <users.json 的根对象>,
}
```

在 `run.py` 里这份字典被放进 **`agent.state["datas"]`**（键名是字符串 **`"datas"`**）。工具里典型写法是：

```30:31:tools/get_order_details.py
    datas = agent.state.get("datas") or {}
    orders = datas.get("orders", {})
```

因此：**`datas` = 整个模拟电商库的根对象**，下面只有三棵「表」：`users`、`products`、`orders`。`data/readme.md` 用一句话概括了这三份文件各自扮演的数据库角色。

---

## 2. `datas["users"]` —— 用户表

**根类型**：`dict[str, dict]`  
**键（key）**：`user_id` 字符串，例如 `"noah_brown_6181"`、`"yusuf_rossi_9620"`（任务里 `Task.user_id` 通常就是这个）。

**每个用户的 value** 大致包含：

| 字段              | 含义                                                         |
| ----------------- | ------------------------------------------------------------ |
| `name`            | `first_name` / `last_name`                                   |
| `address`         | `address1`, `address2`, `city`, `state`, `country`, `zip`    |
| `email`           | 邮箱字符串                                                   |
| `payment_methods` | 字典：**键**是支付方式 id（如 `credit_card_7815826`），**值**是对象：`source`（`paypal` / `credit_card` / `gift_card` 等）、卡品牌/后四位、礼品卡 `balance`、`id` 等 |
| `orders`          | **字符串列表**，元素是订单号，如 `"#W7678072"`，指向 `datas["orders"]` 里的键 |

**用途**：`find_user_id_by_email`、`find_user_id_by_name_zip`、`get_user_details`、`modify_user_address` 等读/改这里；换货、退货、改单支付等也会查该用户下是否有对应 `payment_method_id`。

---

## 3. `datas["products"]` —— 商品 / SPU + 变体

**根类型**：`dict[str, dict]`  
**键（key）**：**`product_id`**（SPU / 商品族 id），例如 `"9523456873"`。

**每个商品的 value** 大致包含：

| 字段         | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| `name`       | 商品展示名，如 `"T-Shirt"`                                   |
| `product_id` | 与外层键一致，冗余一份                                       |
| `variants`   | **字典**：键为 **`item_id`**（某个具体 SKU / 变体），值为该变体详情 |

**每个 variant（`variants[item_id]`）** 常见字段：

| 字段        | 含义                                           |
| ----------- | ---------------------------------------------- |
| `item_id`   | 与键相同，具体可库存、可下单的 **变体 id**     |
| `options`   | 描述规格：颜色、尺寸、材质等（键值随品类变化） |
| `available` | 是否可售（`true`/`false`）                     |
| `price`     | 价格（浮点数）                                 |

**重要区分**（看工具、看 `Task.actions` 时很容易混）：

- **`product_id`**：一整款商品（下面挂很多 `variants`）。
- **`item_id`**：该款下的 **某一个具体变体**；订单行、换货参数里经常出现的是 **`item_id`**（有时任务里写的 `get_product_details` 的 `product_id` 参数名指的是「商品族 id」，和 JSON 顶层键一致）。

---

## 4. `datas["orders"]` —— 订单表

**根类型**：`dict[str, dict]`  
**键（key）**：**`order_id`**，带 `#` 前缀，例如 `"#W2611340"`（与 `users[].orders` 里字符串一致）。

**每个订单的 value** 常见字段（结合样例）：

| 字段              | 含义                                                         |
| ----------------- | ------------------------------------------------------------ |
| `order_id`        | 与键一致                                                     |
| `user_id`         | 所属用户 id，对应 `users` 的键                               |
| `address`         | 本单配送地址（结构与用户地址类似）                           |
| `items`           | **列表**：订单行，每一行是一笔「买了哪个变体」               |
| `fulfillments`    | 物流/履约：如 `tracking_id` 列表、`item_ids`（本批发了哪些行项目） |
| `status`          | 订单状态（如 `processed` 等；其它任务里还会出现待发货、已送达等，工具里会校验） |
| `payment_history` | 列表：`transaction_type`、`amount`、`payment_method_id` 等   |

**`items` 里每一行** 常见字段：

| 字段         | 含义                                                         |
| ------------ | ------------------------------------------------------------ |
| `name`       | 商品名（冗余可读）                                           |
| `product_id` | 商品族 id                                                    |
| `item_id`    | **本行订购的具体变体 id**（和 `products[*].variants` 的键对应） |
| `price`      | 成交价                                                       |
| `options`    | 该变体规格快照                                               |

**用途**：`get_order_details`、`cancel_pending_order`、`modify_pending_order_*`、`exchange_delivered_order_items`、`return_delivered_order_items` 等主要改这里，并可能联动改 `users`（例如订单列表是否更新取决于工具实现）。

---

## 5. 三个顶层键如何一起被「一条任务」用到

用你之前看过的换货题来串：

1. **`users`**：用姓名+邮编找到 `user_id`，再查 `payment_methods` 里是否有任务要求的 `credit_card_9513926` 等。
2. **`orders`**：用 `#W2378156` 拉出 `items`，得到当前行的 `item_id`（旧货）；执行 `exchange` 后这些行会变成新的 `product_id` / `item_id` / `price` / `options`。
3. **`products`**：用 `product_id` 或变体信息查「clicky / Google Home」等是否符合，选目标 **`item_id`** 作为 `new_item_ids`。

判分时对 **`agent.state["datas"]` 整体做 hash**，所以任意一张「表」改错都会导致与 golden 重放结果不一致。

---

## 6. 实现细节（读代码时有用）

- **`OrderedDict`**：`load_data` 用 `object_pairs_hook=OrderedDict`，保证 JSON 对象内 **键顺序稳定**，同一逻辑下序列化/hash 更可复现（对「整库 hash」类评估有意义）。
- **文件名 vs 内存键**：磁盘上是 `users.json`、`products.json`、`orders.json`；进内存后键名是 **`users` / `products` / `orders`**（复数），和 `readme.md` 一致。

如果你接下来读某个工具（例如 `exchange_delivered_order_items.py`），就对照上面四类 id：**`user_id`、`order_id`、`product_id`、`item_id`** 分别在三层结构的哪一层出现，会顺很多。
