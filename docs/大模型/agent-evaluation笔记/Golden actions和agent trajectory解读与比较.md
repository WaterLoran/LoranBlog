# Golden actions和agent trajectory解读与比较

## Golden actions（标准答案动作）

可以把它想成：**出题人写在卷子背后的「参考答案步骤清单」**。

- 每一条是一个小条目：**先干什么、再干什么**（例如先查用户，再查订单，再换货）。
- 每一步写得很“死板”：**工具名叫什么、参数具体填哪些 ID**。
- 它不代表顾客在对话里说了什么，而是：**如果完全按这套操作去改系统里的假数据库，最后数据库应该变成什么样**。

一句话：**Golden actions = 标注好的「正确办事流程（工具版）」**，用来推出 **「正确的最终世界长什么样」**。

---

## 智能体轨迹（agent trajectory）

可以把它想成：**你家客服机器人这次接热线，真实留下的通话与操作记录**。

- 里面有：**顾客一句、客服一句**（自然语言），以及客服中间可能调用的 **查单、改地址、换货** 等工具调用。
- 顺序和内容 **不固定**：它可能多问两句、多查几次、先想想再动手、甚至走了弯路又纠正。
- 关心的不只是“最后一句说了啥”，还包括：**中间调了哪些工具、怎么调用的**（取决于你保存的轨迹格式）。

一句话：**智能体轨迹 = 这次任务里真实发生的「对话 + 模型行为 + 工具调用」记录**。

---

## 两者怎么比（通俗对照）

| 对比点                     | Golden actions                                               | 智能体轨迹                                                   |
| -------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **谁产生的**               | 出题/标注人员事先写好                                        | 模型运行时自动生成                                           |
| **像什么**                 | 标准答案的步骤清单                                           | 真实通话与操作流水                                           |
| **是否只有一种说法**       | 工具与参数通常 **固定**                                      | 对话可以换很多种说法                                         |
| **主要用来干什么**         | 在干净数据库上 **重放**，得到 **标准最终状态**（再和真实跑完的数据库比） | 用来分析 **过程是否合理**、做轨迹匹配、给 LLM Judge 看、排查为啥错 |
| **在本项目里和判分的关系** | 通过重放定义 **「世界对不对」** 的参照                       | **不强制**逐步和 golden 一模一样；更常看 **最终数据库** 或另做轨迹评估 |

---

## 一个生活类比

- **Golden actions**：菜谱上写的「先焯水 3 分钟，再下料，盐 5g」——步骤和用量都写死。
- **智能体轨迹**：你实际做菜时录的视频——你可能先尝了尝、多搅了两下、中间还接了电话，但最后也可能做出同一盘菜。

**本仓库里「主判分」更像**：不强制你炒菜动作和视频里每一步都一样，而是看 **最后上桌的菜（数据库状态）** 是否和按菜谱做出来的一样。  
**轨迹评估**才更像：还要看你的 **操作习惯、顺序、有没有多余或危险步骤**。

这样记：**Golden actions 偏「标准工序」；智能体轨迹偏「真实录像」。**
