# Agent所能使用的工具解读

下面按 **`tools/__init__.py` 里 `ALL_TOOLS` 的 16 个工具**（与 README「16 个工具」一致）说明：**典型用途** + **调用时传入的参数字段**（与各自 `TOOL_SPEC["inputSchema"]` 一致）。Strands 实际调用时参数在 **`tool["input"]`** 里，名称与下表「参数」列一致。

---

## 1. 身份与用户资料

| 工具名                         | 用途场景                                                     | 参数（全部必填）                                             |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **`find_user_id_by_email`**    | 顾客提供了邮箱时，查系统里的 **`user_id`**；查不到会报错。   | **`email`**：字符串，如 `something@example.com`。            |
| **`find_user_id_by_name_zip`** | 没有邮箱或邮箱查不到时，用 **名 + 姓 + 邮编** 查 `user_id`。 | **`first_name`**, **`last_name`**, **`zip`**：字符串。       |
| **`get_user_details`**         | 已有 `user_id` 后，查 **用户档案 + 关联订单列表** 等。       | **`user_id`**：如 `sara_doe_496`。                           |
| **`modify_user_address`**      | 修改用户 **默认地址**（改 `users` 里地址）。说明里要求：先向用户解释并拿到明确 **是/否** 再执行。 | **`user_id`**；**`address1`**, **`address2`**, **`city`**, **`state`**, **`country`**, **`zip`**（`address2` 可为空串如 `''`）。 |

---

## 2. 商品与目录

| 工具名                       | 用途场景                                                     | 参数                                                         |
| ---------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **`list_all_product_types`** | 浏览全店 **商品类型名称 + `product_id`**（约 50 类），用于「有哪些品类 / 某类 id 是多少」类问题。 | **无参数**（`properties` 为空，`required` 为空）。           |
| **`get_product_details`**    | 查某个 **商品族（SPU）** 的库存与变体：各 **`item_id`**、规格 `options`、`available`、`price` 等。 | **`product_id`**：字符串；**注意与订单行里的 `item_id` 不同**。 |

---

## 3. 订单查询

| 工具名                  | 用途场景                                       | 参数                                                  |
| ----------------------- | ---------------------------------------------- | ----------------------------------------------------- |
| **`get_order_details`** | 查订单 **状态、行项目、地址、支付、物流** 等。 | **`order_id`**：必须以 **`#`** 开头，如 `#W0000000`。 |

---

## 4. 待处理订单（`status == pending`）上的写操作

| 工具名                             | 用途场景                                                     | 参数                                                         |
| ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **`cancel_pending_order`**         | **取消**尚未进入已发货/已完成流程的订单；会改状态并退款逻辑（礼品卡即时等）。需先说明并让用户 **明确确认**。非 pending 不能取消。 | **`order_id`**（带 `#`）；**`reason`**：枚举 **`"no longer needed"`** 或 **`"ordered by mistake"`**。 |
| **`modify_pending_order_address`** | 改 **待发货订单**的收货地址。需用户确认。                    | **`order_id`**；**`address1`**, **`address2`**, **`city`**, **`state`**, **`country`**, **`zip`**。 |
| **`modify_pending_order_payment`** | 改 **待处理订单**的支付方式（用于扣款/退款路径）。需用户确认。 | **`order_id`**；**`payment_method_id`**（如 `gift_card_*` / `credit_card_*`，可从用户或订单信息查）。 |
| **`modify_pending_order_items`**   | 把 pending 订单里某些行 **换成同 `product_id` 下的其它 `item_id`**（改规格/变体）；**每单只能成功调用一次**；可能产生价差，用 `payment_method_id` 处理。需用户确认。 | **`order_id`**；**`item_ids`**：字符串数组（当前行 `item_id`，可重复表示多件）；**`new_item_ids`**：字符串数组，与 `item_ids` **等长、按位置一一对应**；**`payment_method_id`**。 |

---

## 5. 已送达订单（`status == delivered`）上的写操作

| 工具名                               | 用途场景                                                     | 参数                                                         |
| ------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **`exchange_delivered_order_items`** | **换货**：已送达订单里指定行换成 **同一 `product_id` 下** 的其它变体；价差走 `payment_method_id`。说明：**退货或换货整体只能由 agent 成功做一类一次**（以工具描述为准）。需用户确认。 | **`order_id`**；**`item_ids`**；**`new_item_ids`**（与 pending 修改相同语义：等长、按位对应、同品）；**`payment_method_id`**。 |
| **`return_delivered_order_items`**   | **退货**：已送达订单中指定 `item_id` 发起退货；订单会变为类似 **`return requested`**；退款走 `payment_method_id`；后续邮件为模拟说明。需用户确认。 | **`order_id`**；**`item_ids`**：要退的行；**`payment_method_id`**。 |

---

## 6. 通用辅助与转人工

| 工具名                         | 用途场景                                                     | 参数                                                         |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **`calculate`**                | 算 **四则运算** 表达式（价格、数量等），不允许危险字符。     | **`expression`**：字符串，如 `2 + 2`；仅数字、`+ - * / ( ) .` 与空格。 |
| **`think`**                    | **不写库、不拉新信息**，把推理记进轨迹（描述里写 append thought；实现上返回空文本）。复杂推理或「草稿记忆」时用。 | **`thought`**：字符串。                                      |
| **`transfer_to_human_agents`** | 用户 **明确要求人工**，或 **当前工具无法解决** 时转人工；环境把它当 **终止类工具**（`env_litellm` 里与 `terminate_tools` 相关）。 | **`summary`**：把用户问题总结成一段字符串。                  |

---

## 传参时最容易混的三点

1. **`order_id`**：一律 **`#W...`** 格式。  
2. **`product_id` vs `item_id`**：`get_product_details` 用 **`product_id`**；订单行、换货/改 pending 行、退货用的是 **`item_id`**（某 SKU 变体）。  
3. **`item_ids` / `new_item_ids`**：两个数组 **长度必须相同**，且 **同一位置** 表示「把这一行从旧变体换成新变体」，新变体须属于 **同一 `product_id`**（由实现校验）。

更细的边界（例如哪些 `status` 可取消/可换）以各 **`tools/*.py`** 里实现与 `wiki.md` 政策为准；上表与官方 `TOOL_SPEC` 一致。若要「模型侧」何时必须确认用户，优先看各工具 **`description`** 里写的 **explicit user confirmation (yes/no)**。
