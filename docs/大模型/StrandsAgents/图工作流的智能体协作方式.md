# 图工作流的智能体协作方式

图工作流是Strands Agents提供的确定性多智能体协作模式，它通过构建有向图（DAG）来组织多个AI智能体的协作流程。如果把Swarm比作一个自主协作的爵士乐队，图工作流就像一个严格按照乐谱演奏的交响乐团[reference:0]。

它的核心思想是：你定义好一系列智能体节点（Node）以及它们之间的依赖关系（Edge），框架便会自动解析依赖关系并顺序执行。一个节点的输出会自动传递给它的下游节点，并且**支持并行执行**（若多个节点无依赖可同时运行）和**条件分支**（根据输出决定下一节点）[reference:1][reference:2]。

### 🏗️ 核心组件与上下文管理

构建一个图工作流主要涉及三个核心组件[reference:3]：

1.  **`GraphNode` (节点)**：图中的执行单元，可以是一个AI智能体、一个确定性函数（如自定义节点），甚至是另一个图或Swarm[reference:4]。
2.  **`GraphEdge` (边)**：定义节点间的依赖关系。最基本的是数据流的依赖（A->B，先执行A再执行B），也可以附加一个判断函数来实现**条件路由**[reference:5][reference:6]。
3.  **`GraphBuilder` (构建器)**：提供链式调用来构造图，用于添加节点、定义边、设置入口点等[reference:7]。

**上下文传递**：当一个下游节点（如报告撰写员）依赖于多个上游节点（如研究员和核查员）时，Strands会自动将所有上游节点的输出，连同最开始的原始任务，一起作为输入传递给下游节点[reference:8]。

### 🕸️ 三种核心工作流类型

基于上述组件，图工作流可以构建以下几种典型的执行模式：

#### 1. 线性流水线 (Sequential Pipeline)

这是最简单的图工作流形式，智能体按固定的、线性的顺序执行，一个接一个地处理任务。

```python
from strands import Agent
from strands.multiagent.graph import GraphBuilder

# 1. 定义各司其职的智能体
researcher = Agent(
    name="Researcher",
    system_prompt="你是一名研究员，负责收集关于给定主题的核心事实和关键信息。请简要列出要点。"
)
analyst = Agent(
    name="Analyst",
    system_prompt="你是一名数据分析师。你的任务是基于输入信息，撰写一份简洁、清晰的分析报告。"
)
report_writer = Agent(
    name="ReportWriter",
    system_prompt="你是一名报告撰写员。你的任务是基于分析结果，写出一份结构完整、措辞专业的正式报告。"
)

# 2. 构建线性执行图
graph_builder = GraphBuilder()
graph_builder.add_node(researcher)
graph_builder.add_node(analyst)
graph_builder.add_node(report_writer)

# 3. 定义数据流的边
graph_builder.add_edge(Research="researcher", Analyst="analyst")
graph_builder.add_edge(Analyst="analyst", ReportWriter="report_writer")

# 4. 设置入口点
graph_builder.set_entry_point("researcher")

# 5. 构建并执行
graph = graph_builder.build()
result = graph.run("人工智能在医疗领域的应用")
print(result["final_output"])
```
**代码解析**：
*   首先，我们创建了三个职责明确的AI智能体：`Researcher`、`Analyst`和`ReportWriter`。
*   然后，通过`add_edge(researcher, analyst)`定义了它们之间的依赖关系。这告诉Strands：必须先执行完`researcher`，才能执行`analyst`，并且`researcher`的输出会自动成为`analyst`的输入。

#### 2. 扇出扇入与条件路由 (Fan-out & Conditional Routing)

当一个下游节点依赖于多个上游节点的结果时，所有上游节点会并行执行（扇出），再将所有结果汇总给下游（扇入）。同时，可以在边（Edge）上附加条件函数（`condition`）来决定是否要执行下一个节点。

```python
from strands import Agent
from strands.multiagent.graph import GraphBuilder

# 创建三个独立的智能体
# ... (与线性流水线类似，定义 researcher, fact_checker, report_writer)
researcher = Agent(name="Researcher", ...)
fact_checker = Agent(name="FactChecker", ...)
report_writer = Agent(name="ReportWriter", ...)

# 条件函数：检查输入中是否包含特定关键词
def check_negative_keywords(graph_state):
    """
    一个决定是否将报告移交审核的条件函数。
    Args:
        graph_state: 包含当前节点执行结果的对象。
    Returns:
        bool: 如果结果为 True，则执行此 Edge 指向的目标节点。
    """
    # 获取当前执行节点的结果
    current_result = graph_state.get_result_for_node("ReportWriter")
    if not current_result:
        return False
    # 如果报告中包含"争议"或"敏感"词汇，则返回 True，触发审核
    sensitive_words = ["争议", "敏感", "机密"]
    return any(word in current_result for word in sensitive_words)

# 构建图
graph_builder = GraphBuilder()
graph_builder.add_node(researcher)
graph_builder.add_node(fact_checker)
graph_builder.add_node(report_writer)
# 添加一个作为“审核员”的智能体节点
reviewer = Agent(name="Reviewer", system_prompt="你是一个严格的审核员，负责审查报告内容，确保其合规性和准确性。")
graph_builder.add_node(reviewer)

# 定义依赖关系
graph_builder.add_edge(researcher, report_writer)
graph_builder.add_edge(fact_checker, report_writer)  # ReportWriter 依赖 Researcher 和 FactChecker
graph_builder.add_edge(report_writer, reviewer, condition=check_negative_keywords)  # 条件边，仅当 report 包含敏感词时执行

graph_builder.set_entry_point("researcher")
graph = graph_builder.build()
```
**代码解析**：
*   `add_edge(fact_checker, report_writer)` 表明`report_writer`依赖于`researcher`和`fact_checker`两个节点，Strands会自动并行执行它们，并将结果一同传给`report_writer`[reference:9]。
*   最后的 `add_edge(report_writer, reviewer, condition=check_negative_keywords)` 添加了一个**条件边**。`condition` 参数接收一个函数，该函数会基于当前的`GraphState`（包含所有已执行节点的结果）来决定是否应该执行`reviewer`节点[reference:10]。这使得工作流可以智能地选择路径。

#### 3. 反馈循环与迭代优化 (Feedback Loop)

利用条件边和循环，可以创建反馈循环，实现内容的迭代式优化，直到满足特定标准。

```python
from strands import Agent
from strands.multiagent.graph import GraphBuilder
from strands import tool

@tool
def evaluate_content(content: str) -> dict:
    """
    一个确定性节点，用于评估内容质量。
    Args:
        content: 需要评估的内容。
    Returns:
        一个包含分数和反馈的字典。
    """
    # ... 这里可以接入复杂的评分逻辑或人工确认 ...
    # 示例逻辑：如果内容长度少于20字，认为不合格
    if len(content) < 20:
        return {"approved": False, "feedback": "内容过于简短，请详细阐述。"}
    else:
        return {"approved": True, "feedback": "内容质量合格。"}

# 创建智能体
writer = Agent(name="Writer", system_prompt="你是一个内容创作者，根据任务要求和反馈意见，生成或改进内容。")
finalizer = Agent(name="Finalizer", system_prompt="你是一个文案编辑，负责对内容进行最终润色，使其更加流畅和专业。")

# 构建图
graph_builder = GraphBuilder()
graph_builder.add_node(writer)
graph_builder.add_custom_node("QualityChecker", evaluate_content) # 添加一个自定义确定性节点
graph_builder.add_node(finalizer)

# 定义条件边：如果质量检查未通过，则重新执行 writer 节点
def route_after_checker(graph_state):
    checker_result = graph_state.get_result_for_node("QualityChecker")
    if checker_result and checker_result.get("approved"):
        return "finalizer"  # 如果通过，前往 finalizer
    else:
        return "writer"     # 如果未通过，返回 writer 节点进行重写

graph_builder.add_edge(writer, "QualityChecker")
# 为节点添加条件路由
graph_builder.add_conditional_edges("QualityChecker", route_after_checker, {"finalizer": finalizer, "writer": writer})

graph_builder.set_entry_point("writer")
graph_builder.set_max_node_executions(5) # 设置最大执行次数，防止无限循环
graph = graph_builder.build()

result = graph.run("写一篇关于'云计算优势'的简短介绍。")
```
**代码解析**：
*   `add_custom_node` 添加了一个不使用LLM的确定性节点（如调用API或执行本地Python函数），用于评估质量[reference:11]。
*   `add_conditional_edges` 定义了核心的反馈循环：若质量评估未通过（`approved`为`False`），则再次执行`writer`节点，形成“**写->评估->修改**”的闭环[reference:12]。
*   `set_max_node_executions(5)` 设置了全图的总执行次数限制，这是防止图因无限循环而崩溃的重要安全措施[reference:13]。

### 💎 总结

Strands Agents的图工作流是一种强大的工具，适用于需要**清晰步骤、固定流程和稳定产出**的场景，例如数据处理流水线、内容审核系统或自动化报告生成等。通过`GraphBuilder`可以轻松地构建和组合这些工作流，甚至可以将一个完整的图作为节点嵌套进另一个图中，构建出极其复杂且层次分明的系统[reference:14]。
