# 模块化工具定义

关于 `TOOL_SPEC`，简单来说，它是一种在Strands Agents框架中定义工具的“传统”方法，相比`@tool`装饰器，它能提供更细粒度的控制。

### 对比 @tool 与 TOOL_SPEC

在深入代码之前，我们先来理解一下这两种工具定义方式的区别，这能帮助你根据场景选择最合适的方法。

| 对比维度     | `@tool` 装饰器 (便捷派)                                      | `TOOL_SPEC` (掌控派)                                         |
| :----------- | :----------------------------------------------------------- | :----------------------------------------------------------- |
| **定义位置** | 在单个 `.py` 文件内部，通过装饰器定义                        | 通常作为独立的 `.py` 模块文件                                |
| **核心构成** | 一个被装饰的Python函数，依赖类型提示和文档字符串             | 一个明确的 `TOOL_SPEC` 字典 + 一个同名的实现函数             |
| **上手速度** | **极高**。专注于业务逻辑，框架自动解析参数[reference:0][reference:1] | **一般**。需要手动编写完整的工具规格和实现                   |
| **功能控制** | **受限**。工具名称和参数Schema由函数签名和文档自动生成[reference:2] | **完全控制**。可以精细控制工具的`name`, `description`, `input_schema`[reference:3][reference:4] |
| **适用场景** | 快速原型、内部工具、个人项目[reference:5]                    | 生产环境、团队协作、可复用工具库、需要精确控制Schema的场景[reference:6][reference:7] |

**结论**：如果你追求极致的开发效率和简洁性，`@tool`装饰器是你的最佳拍档。而当你需要构建一个可维护、可复用且对接口有精确要求的工具库时，模块化的 `TOOL_SPEC` 方式会展现出它的强大优势。

---

### 模块化工具定义 (TOOL_SPEC) 详解

一个模块化的Strands工具，本质是一个遵循特定约定的Python文件。它主要包含两个部分[reference:8][reference:9]：

1.  **`TOOL_SPEC` 变量**：一个Python字典，严格遵循JSON Schema规范，用于向框架描述工具的“身份”和“使用说明”[reference:10]。
2.  **`TOOL_FUNC` 函数**：一个与`TOOL_SPEC`中`name`同名的Python函数，包含了工具实际执行的业务逻辑。

#### 1. 动手实现：构建一个基础模块化工具

我们来创建一个名为 `text_stats` 的工具，用于统计一段文本的字数和句数。

```python
# text_stats.py
import re

TOOL_SPEC = {
    "name": "text_stats",  # [1] 工具的唯一标识符
    "description": "统计给定文本的字数（汉字或单词）和句数。", # [2] 告诉模型该工具的功能
    "input_schema": {      # [3] 定义模型调用时需要提供的参数及其格式
        "type": "object",
        "properties": {
            "text": {
                "type": "string",
                "description": "需要被统计的原始文本。",
            },
        },
        "required": ["text"],  # 指明哪些参数是模型必须提供的
    },
}

# [4] 实现具体的统计逻辑，函数名必须与 TOOL_SPEC 中的 "name" 一致
def text_stats(text: str) -> str:
    """
    统计文本的字数和句数。
    """
    # 统计字数：匹配所有非空字符（对中英文都有效）
    word_count = len(re.findall(r'\S', text))
    
    # 统计句数：按句号、问号、感叹号、分号分割
    sentence_count = len(re.split(r'[。！？；]', text)) - 1
    
    # 返回一个字符串，该字符串将作为模型的结果
    return f"该文本包含 {word_count} 个字符，{sentence_count} 个句子。"
```

**代码关键点解读：**
*   `name` (`text_stats`)：这是Agent调用此工具的“命令”，**必须**与实现函数同名[reference:11]。
*   `description`：用自然语言清晰描述工具功能，这是模型理解何时使用它的**核心依据**。
*   `input_schema`：这是用JSON Schema格式定义的参数规范，其中`type: "object"`表示参数是一个对象，`properties`里定义了具体的参数名和类型，`required`则指定了哪些参数是模型**必须提供**的。框架会根据这个schema自动验证模型传入的参数，确保调用合法[reference:12]。
*   `text_stats`函数：这是工具的逻辑核心，它接收经过验证的`text`参数并返回一个字符串结果，Agent会把这个结果融入对话中。

#### 2. 代码复用：构建复杂的模块化工具

模块化工具的另一个强大之处在于，你可以在工具内部调用其他函数，实现复杂的业务逻辑。

```python
# complex_task.py

# 假设这是一个公司内部的复杂权限检查函数
def _check_user_permission(user_id: str, action: str) -> bool:
    """内部函数：模拟权限检查"""
    # ... 这里是查询数据库或其他复杂逻辑的模拟代码
    print(f"   -> 正在为 {user_id} 检查权限：{action}")
    return True # 假设权限通过

TOOL_SPEC = {
    "name": "process_sensitive_data",
    "description": "处理敏感数据前，必须调用此工具。它会执行一系列安全检查。",
    "input_schema": {
        "type": "object",
        "properties": {
            "user_id": {"type": "string", "description": "请求操作的用户ID"},
            "data": {"type": "string", "description": "需要处理的数据内容"},
        },
        "required": ["user_id", "data"],
    },
}

def process_sensitive_data(user_id: str, data: str) -> str:
    """工具函数，内部调用其他复杂逻辑"""
    # 1. 调用内部函数进行权限检查
    has_permission = _check_user_permission(user_id, "sensitive_action")
    
    if not has_permission:
        return f"错误：用户 {user_id} 没有执行此操作的权限。"
    
    # 2. 执行核心数据处理（此处为示例）
    processed_data = f"已安全处理数据：'{data}'"
    
    # 3. 返回处理结果
    return processed_data
```

#### 3. 装载与使用：让智能体获得这些工具

定义好工具模块后，将其加载到Agent中的方式非常灵活，主要有以下三种：

```python
from strands import Agent

# 方式一：通过文件路径加载单个模块
agent1 = Agent(tools=["/path/to/text_stats.py"])

# 方式二：通过文件路径加载多个模块
agent2 = Agent(tools=["/path/to/text_stats.py", "/path/to/complex_task.py"])

# 方式三（高级）：通过目录自动加载和热重载
# 只需将 .py 工具文件放入项目根目录下的 ./tools 文件夹
# 并在初始化Agent时启用目录加载功能即可
agent3 = Agent(load_tools_from_directory=True)

# 之后，Agent就能自动使用这些工具了
result = agent1("帮我统计一下这句话的字数和句数。")
print(result)
```

通过路径加载时，直接传入`.py`文件的路径字符串即可。更高效的是目录加载：`load_tools_from_directory=True`参数会指示Strands自动发现并加载`./tools/`目录下的所有有效工具[reference:13]。此机制还支持**热重载（Hot Reload）**，即当你修改`./tools/`目录下的工具代码时，使用这些工具的Agent会在下一次调用时自动加载最新版本，这在开发调试时极为便利[reference:14]。

### 💎 总结

`TOOL_SPEC` 模块化工具定义方式，为你提供了在生产环境中构建和复用工具的坚实基础。它的核心在于通过清晰的规格说明，让AI模型能准确理解并调用你的工具。在项目实践中，你可以轻松地在 `@tool` 装饰器（用于快速原型）和 `TOOL_SPEC` 模块化定义（用于生产级工具库）之间进行选择或组合使用。
