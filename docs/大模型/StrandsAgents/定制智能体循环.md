# 定制智能体循环

定制智能体循环的核心机制是**钩子系统（Hooks）**。它允许你在智能体执行的关键阶段，像“观察者”一样注入自定义逻辑，实现从监控到动态干预的全面控制。

以下是一个完整的技术框架和代码示例：

### 🔍 钩子系统全览：智能体生命周期的观察者

Strands 的钩子系统是一个基于发布-订阅模式的事件监听机制[reference:0]。你只需定义一个回调函数，并将其注册到智能体上。当智能体运行时，这些事件被触发，你的逻辑便会自动执行。

事件在智能体的生命周期中严格按顺序发生，主要有以下几类[reference:1][reference:2][reference:3]：

#### 1. 稳定（Stable）事件：可靠的基础监控

以下事件接口稳定，适合在生产环境中使用[reference:4]：

*   **`BeforeInvocationEvent`**：发生在智能体**开始**处理任何用户请求之前，适合执行请求日志、权限校验等初始化操作。
*   **`AfterInvocationEvent`**：发生在智能体**完成**所有处理后（无论成功或失败），适合进行资源清理、性能指标记录等收尾工作[reference:5]。此事件使用**逆序回调**，确保后注册的钩子（如清理钩子）先执行[reference:6]。

#### 2. 实验性（Experimental）事件：强大的动态干预

以下事件能让你深度介入智能体的内部运行，但请注意其API在未来版本中可能调整[reference:7]：

*   **`BeforeToolInvocationEvent`**：在工具**即将执行**前触发。你可以通过修改事件的属性，来**动态改变**即将调用的工具或其参数，是实现“人工确认”等高级功能的关键[reference:8][reference:9]。
*   **`AfterToolInvocationEvent`**：在工具**执行完成**后触发。你可以修改事件的 `result` 属性，对工具的执行结果进行后处理，例如格式化、缓存或添加额外信息[reference:10][reference:11]。
*   **`BeforeModelInvocationEvent`** / **`AfterModelInvocationEvent`**：分别在调用大模型**前后**触发。可用于修改发送给模型的请求，或处理模型返回的原始响应[reference:12][reference:13]。

### 💻 实战代码示例

#### 1. 基础监控与状态管理

这个例子展示了如何用稳定事件进行基础的调用计数和性能追踪。

```python
import time
from strands import Agent
from strands.hooks import BeforeInvocationEvent, AfterInvocationEvent

# 准备一个用于存储自定义状态的字典
agent_state = {"call_count": 0, "last_call_duration": None}

# 钩子回调函数
def before_invocation_handler(event: BeforeInvocationEvent):
    # 通过 event.agent 访问智能体实例
    agent_state["call_count"] += 1
    print(f"👉 [HOOK] 第 {agent_state['call_count']} 次调用开始")
    # 将当前时间戳存入智能体状态，供后续钩子使用
    event.agent.state["invoke_start_time"] = time.time()

def after_invocation_handler(event: AfterInvocationEvent):
    # 从智能体状态中读取开始时间
    start_time = event.agent.state.get("invoke_start_time")
    if start_time:
        duration = time.time() - start_time
        agent_state["last_call_duration"] = duration
        print(f"✅ [HOOK] 调用完成，耗时: {duration:.2f}秒")
    print(f"📊 [HOOK] 当前状态: {agent_state}")

# 创建智能体并注册钩子
agent = Agent(tools=[])
agent.hooks.add_callback(BeforeInvocationEvent, before_invocation_handler)
agent.hooks.add_callback(AfterInvocationEvent, after_invocation_handler)

# 测试
response = agent("简单介绍一下你自己。")
print(f"🤖 智能体回答: {response}")
```

**代码解读**：
*   **`before_invocation_handler`**：每次调用前，增加计数器并记录开始时间到 `agent.state` 中。`event.agent` 让你能直接与当前智能体交互。
*   **`after_invocation_handler`**：调用结束后，计算耗时并打印状态。这里的 `AfterInvocationEvent` 即使在调用过程中发生错误也会被触发，确保了清理逻辑的可靠性。

#### 2. 高级干预：动态修改工具行为（人工确认模式）

这是钩子系统最强大的场景之一。本例展示如何在执行 `delete_file` 这种高风险工具前，强制要求人工确认。

```python
import asyncio
from strands import Agent, tool
# 注意：实验性钩子需要从 experimental 模块导入
from strands.experimental.hooks import BeforeToolInvocationEvent

@tool
def delete_file(file_path: str) -> str:
    """模拟删除文件的危险操作"""
    # 这里应该是真实的文件删除逻辑
    return f"文件 {file_path} 已成功删除。"

# 人工确认逻辑的钩子
def human_approval_hook(event: BeforeToolInvocationEvent):
    # 检查即将被调用的工具名称
    if event.selected_tool and event.selected_tool.name == "delete_file":
        file_path = event.tool_use.input.get("file_path", "未知路径")
        print(f"\n⚠️  [安全钩子] 拦截到危险操作：准备删除文件 '{file_path}'")
        user_input = input("请输入 'yes' 确认删除，输入其他任意内容拒绝: ").strip().lower()
        
        if user_input != 'yes':
            print("🚫 [安全钩子] 操作已被用户拒绝。")
            # 通过抛出一个自定义异常来中断工具的执行
            # 你可以定义自己的异常类型
            raise PermissionError("用户取消了删除操作")
        else:
            print("✅ [安全钩子] 操作已获批准，继续执行。")

agent = Agent(tools=[delete_file])
# 注册实验性钩子
agent.hooks.add_callback(BeforeToolInvocationEvent, human_approval_hook)

# 尝试运行一个危险的命令
try:
    # 假设智能体经过推理后，决定调用 delete_file 工具
    # 这里我们直接模拟调用，在实际应用中，这个调用由智能体自身发起
    response = agent("请帮我删除 /tmp/test.txt 文件。")
    print(f"🤖 智能体回答: {response}")
except PermissionError as e:
    print(f"❌ 程序终止: {e}")
```

**代码解读**：
*   **`human_approval_hook`** 注册在 `BeforeToolInvocationEvent` 上。
*   当智能体准备调用 `delete_file` 时，钩子函数被触发，检查工具名并请求用户输入。
*   如果用户拒绝，钩子抛出 `PermissionError`，从而中断本次工具调用，并向外部程序报告错误。这种模式是实现“人在回路”（Human-in-the-Loop）的绝佳方式[reference:14]。

### 🧩 高级模式：封装逻辑的利器

#### 1. 使用插件（Plugins）封装钩子

对于复杂的钩子逻辑，你可以将其封装成一个可复用的**插件**（Plugin），让代码更模块化[reference:15]。

```python
from strands import Agent, Plugin
from strands.experimental.hooks import AfterToolInvocationEvent

# 定义一个用于记录工具耗时的插件
class TimingPlugin(Plugin):
    name = "timing_plugin"

    # 使用 @hook 装饰器声明这是一个钩子方法
    # 方法签名中的类型注解会告诉框架它应该监听哪个事件
    @hook
    def on_after_tool(self, event: AfterToolInvocationEvent):
        if event.selected_tool:
            print(f"⏱️  [插件] 工具 '{event.selected_tool.name}' 执行完成")

# 使用时，只需将插件实例传入 Agent
agent = Agent(tools=[], plugins=[TimingPlugin()])
```

#### 2. 使用图（Graph）创建反馈循环

对于更复杂的、确定性的多智能体协作，你可以使用 Strands 的 **图（Graph）** 功能，它允许你构建带有循环和条件分支的复杂工作流[reference:16][reference:17]。

```python
from strands import Agent
from strands.graph import Graph, conditional_edge

writer = Agent(name="Writer", system_prompt="你是一位创意作家。")
checker = Agent(name="Checker", system_prompt="你是一位严格的编辑。")

# 定义一个条件边，决定是否继续循环
@conditional_edge
def should_continue(content: str) -> str:
    # 如果内容不合格，则返回 "writer" 节点名称，触发循环
    return "writer" if "不合格" in content else "finalizer"

# 构建图：writer -> checker -> [条件] -> (writer 或 finalizer)
graph = Graph()
graph.add_node(writer)
graph.add_node(checker)
graph.add_edge(writer, checker)
graph.add_conditional_edge(checker, should_continue)
```

这种模式非常适合文档起草与审核、代码生成与测试等需要迭代优化的任务[reference:18]。

### ⚠️ 重要注意事项

*   **钩子的稳定性**：`BeforeToolInvocationEvent` 等是**实验性**功能，API 在未来可能发生变更。生产环境中使用需谨慎，并关注版本更新[reference:19]。
*   **钩子性能**：钩子是同步执行的，请避免在钩子中执行耗时过长的操作（如复杂的网络请求），以免阻塞整个智能体的运行。
*   **状态访问**：钩子可以通过 `event.agent.state` 访问智能体的**临时状态**，这对于在钩子间传递信息非常有用。

通过灵活运用钩子，你可以将Strands Agents从一个基础的工具调用器，升级为一个完全符合你业务逻辑的、可控的、可观测的自主系统。
