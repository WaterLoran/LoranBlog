# 上下文管理与会话状态

这三种上下文管理机制，分别对应了在不同场景下维持长对话的“默认选择”、“高效压缩”和“持久化方案”。下面通过代码和解释，展示如何将它们应用到Strands Agents项目中。

### 1. 滑动窗口 (Sliding Window)：默认的高效之选

滑动窗口是Strands Agents的**默认上下文管理策略**[reference:0]。它的核心逻辑是：当对话消息超过设定的窗口大小时，自动丢弃最旧的消息，仅保留最近的指定数量[reference:1]。这就像一个只关注最近聊天的智能体。

这种方式非常适合那些**不需要长期记忆**的通用对话任务，如简单的客服问答或信息查询，因为它能有效控制上下文Token消耗，保证响应速度。

下面是一个创建带有滑动窗口策略的Agent的示例，我们将窗口大小设置为10条消息：

```python
from strands import Agent
from strands.agent.conversation_manager import SlidingWindowConversationManager

# 创建一个滑动窗口管理器，指定窗口大小为10条消息
# 这意味着智能体将只记得最近的10条对话记录
window_manager = SlidingWindowConversationManager(
    window_size=10,  # 保留最近的10条消息
    should_truncate_results=True  # 当工具返回结果过大时进行截断，默认为True
)

# 创建Agent时，通过conversation_manager参数传入
agent = Agent(
    name="ShortMemoryBot",
    conversation_manager=window_manager,
    system_prompt="你是一个只能记住最近10次对话的助手。"
)

# 模拟多轮对话
for i in range(15):
    response = agent(f"这是第{i+1}轮对话。")
    print(f"轮次 {i+1}: {response}")
# 在第11轮时，第1轮的消息将被移除，agent不再记得。
```

**代码详解**

*   我们通过 `SlidingWindowConversationManager` 实例化了一个管理器，并设置 `window_size=10`。
*   随后，将这个管理器通过 `conversation_manager` 参数传递给 `Agent` 的构造函数。
*   智能体运行超过10轮后，最早的消息就会被自动丢弃，只保留最近的10条[reference:2]。`should_truncate_results` 参数可以控制是否截断过大的工具返回结果，避免单条消息撑爆上下文[reference:3]。

### 2. 摘要策略 (Summarization)：长对话的“压缩饼干”

对于需要处理非常长对话的场景（如长篇咨询、故事创作），纯丢弃的策略会丢失重要信息。这时就需要**摘要策略**。Strands Agents 提供了内置的 `SummarizingConversationManager`，当上下文窗口即将超限时，它会调用LLM模型将过去的对话压缩成一个摘要，以此“替代”原始消息，从而在保留关键信息的同时，极大地压缩Token数量[reference:4]。

这种策略非常适合**需要长期保留核心信息的任务**，例如一个贯穿全天的旅游规划助手，它需要记住用户之前提及的所有偏好（如“不吃辣”、“喜欢海景”）。

这是一个使用摘要策略的Agent示例：

```python
from strands import Agent
from strands.agent.conversation_manager import SummarizingConversationManager

# 创建一个摘要管理器，指定摘要的触发时机
summarize_manager = SummarizingConversationManager(
    max_context_tokens=4000,      # 上下文窗口Token上限，例如Claude 3 Haiku为4000
    summary_model="claude-3-haiku-20240307", # 用于生成摘要的模型，通常选择轻量级模型
    summary_trigger_tokens=3500,  # 当Token数超过此阈值时触发摘要
    keep_recent_messages=5        # 摘要时，保留最近N条完整消息，不做压缩
)

agent = Agent(
    name="LongMemoryBot",
    conversation_manager=summarize_manager,
    system_prompt="你是一个能记住长对话核心信息的旅行规划助手。"
)

# 模拟一个非常长的对话
agent("我想规划一次云南旅行，预算5000元，大约7天。")
agent("我喜欢自然风光，对历史人文不太感兴趣。")
agent("我是素食主义者，对吃很讲究。")
# ... 后续进行了超过20轮的详细讨论 ...
# 当对话累积的Token接近 max_context_tokens 时，摘要管理器会被自动触发，
# 将前面的对话压缩成一个摘要（例如："用户计划云南7日游，预算5000，偏好自然风光，为素食者"），
# 后续对话将基于这个摘要 + 最近的5条消息进行。
```

**代码详解**

*   `SummarizingConversationManager` 需要你配置几个关键参数：`max_context_tokens`（模型的上下文上限）、`summary_trigger_tokens`（触发摘要的阈值）以及用于生成摘要的 `summary_model`[reference:5]。
*   当智能体的对话历史超过 `summary_trigger_tokens` 时，该管理器会自动触发，调用指定的模型将旧对话压缩为摘要，并保留最近 `keep_recent_messages` 条消息。
*   这确保了长对话的核心信息得以保留，同时不会超出模型的Token限制。你也可以通过继承 `ConversationManager` 类，实现自己的个性化摘要逻辑[reference:6]。

### 3. 会话持久化 (Session Persistence)：让对话永不丢失

前两种策略解决的是在**一次会话**内的记忆问题，而会话持久化则是将整个会话状态（对话历史、Agent状态等）保存到**外部存储**中，让对话可以“关机重启”或“跨服务迁移”[reference:7]。Strands Agents 提供了 `S3SessionManager` 和 `FileSessionManager` 两种内置方案[reference:8]。

这种策略对于**任何生产环境的应用**都至关重要。它让用户可以在不同时间、不同设备上继续之前的对话，或者让无服务器部署的Agent在两次调用间保持状态[reference:9]。

下面是生产环境中最常用的 `S3SessionManager` 示例，它会将会话数据保存在AWS S3中。

```python
import boto3
from strands import Agent
from strands.session.s3_session_manager import S3SessionManager

# 1. 配置AWS S3客户端（确保你的AWS凭证已正确配置）
s3_client = boto3.client('s3', region_name='us-east-1')
bucket_name = "my-agent-sessions-bucket"

# 2. 为特定会话创建一个会话管理器
#    关键的session_id用于唯一标识一个对话
session_manager = S3SessionManager(
    session_id="user_12345_conversation_01", # 唯一会话ID
    bucket=bucket_name,
    s3_client=s3_client,            # 传入已配置的客户端
    prefix="agent_sessions/"        # S3中的路径前缀，用于组织文件
)

# 3. 创建Agent时，通过session_manager参数注入
agent = Agent(
    name="PersistentBot",
    session_manager=session_manager, # 注入会话管理器
    system_prompt="我是一个能记住所有对话的助手。"
)

# 用户第一次交互
agent("你好，我叫张三，喜欢科幻电影。")

# 应用重启或服务迁移后...
# 再次使用同一个 session_id 创建相同的 session_manager
session_manager_recovered = S3SessionManager(
    session_id="user_12345_conversation_01", # 相同的ID
    bucket=bucket_name,
    s3_client=s3_client
)
agent_recovered = Agent(
    name="PersistentBot",
    session_manager=session_manager_recovered,
)

# Agent会自动从S3加载历史对话，并记住之前的信息
response = agent_recovered("你还记得我叫什么名字吗？")
print(response) # 输出应该会提及用户的名字"张三"
```

**代码详解**

1.  **初始化 `S3SessionManager`**：关键是提供唯一的 `session_id` 和 S3存储桶 `bucket`。
2.  **注入 Agent**：将创建好的 `session_manager` 通过 `session_manager` 参数传递给 `Agent` 的构造函数。从此，Agent的每一次对话和状态变化都会被自动持久化到S3[reference:10]。
3.  **跨应用恢复**：当应用重启后，只要使用**相同的 `session_id`** 和S3配置重新创建 `S3SessionManager` 和 `Agent`，智能体就能自动从S3中加载历史记录，无缝恢复对话[reference:11]。这对于Web应用、微服务或Lambda函数等无状态环境至关重要。

### 📚 策略对比

| 特性         | 滑动窗口                  | 摘要策略                     | 会话持久化                 |
| :----------- | :------------------------ | :--------------------------- | :------------------------- |
| **核心目的** | 控制单次会话内的Token消耗 | 在长会话中保留核心信息       | 跨应用、跨设备保存完整会话 |
| **实现方式** | 自动丢弃旧消息            | 将旧消息压缩为摘要           | 将完整状态存入外部存储     |
| **记忆特点** | 短期记忆                  | 压缩的长期记忆               | 永久记忆                   |
| **适用场景** | 通用对话、成本敏感的任务  | 需要保留关键背景的咨询、分析 | 生产环境、多轮复杂应用     |
| **复杂度**   | 低                        | 中                           | 中高（需配置外部存储）     |
| **是否默认** | **是**                    | 否                           | 否                         |

### 💎 总结与学习路径

要掌握Strands Agents的上下文管理，你可以遵循这个路径：

1.  **优先使用滑动窗口**：在绝大多数场景，尤其是开发初期，直接使用默认的滑动窗口策略即可满足需求。
2.  **按需引入摘要策略**：当遇到非常长的对话且需要保留历史信息时，再考虑配置和使用 `SummarizingConversationManager`。
3.  **生产环境标配会话持久化**：**任何面向生产环境的Agent，都应尽早集成会话持久化**。无论是使用 `S3SessionManager` 还是 `FileSessionManager`（用于本地测试），这会让你的Agent真正健壮和可扩展。

这三种策略并非互斥，它们可以组合使用。例如，你可以创建一个使用了**滑动窗口**的Agent，同时启用**会话持久化**来保存每次会话的最终状态，这样在下次调用时，Agent依然能从上次的窗口状态开始。
