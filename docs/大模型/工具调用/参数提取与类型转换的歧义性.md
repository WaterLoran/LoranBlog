# 参数提取与类型转换的歧义性

在工具调用过程中，**参数提取与类型转换的歧义性** 是最常遇到的问题。LLM 生成的参数值在语义上正确，但在格式、类型或取值范围上与工具接口要求不匹配。例如，LLM 输出 `"tomorrow"` 而工具需要 `2025-04-11`；输出 `"3.14"` 字符串而工具需要浮点数；输出 `"high"` 而工具枚举只接受 `"HIGH"`。

下面从 **事前约束、事中转换、事后反馈** 三个层面，给出系统性的解决方案。

---

## 一、事前约束：让 LLM 生成时就减少歧义

### 1. 使用严格的 JSON Schema（含格式、模式、枚举）
在工具描述中，不仅声明类型，还要使用 JSON Schema 的进阶约束字段，引导 LLM 生成规范值。

```json
{
  "type": "object",
  "properties": {
    "date": {
      "type": "string",
      "format": "date",           // 提示 LLM 使用 ISO 8601 日期
      "description": "日期，格式 YYYY-MM-DD，例如 2025-04-11"
    },
    "temperature": {
      "type": "number",           // 明确为数字，不是字符串
      "minimum": -50,
      "maximum": 60
    },
    "unit": {
      "type": "string",
      "enum": ["celsius", "fahrenheit"]   // 仅允许两个值
    }
  }
}
```

### 2. 在描述中给出清晰示例（Few-shot）
在工具的 `description` 或参数描述中，直接提供正确示例，能显著降低歧义。

```text
参数: city (string) - 城市名，使用英文标准名称，例如 "Beijing", "New York"
```

### 3. 使用结构化输出 API（如 OpenAI `strict` 模式）
许多 LLM 提供商支持约束生成（constrained decoding），如 OpenAI 的 `function calling` 默认会校验类型，`response_format` 的 `strict: true` 可强制输出符合 schema 的 JSON。这能杜绝类型错误和额外字段。

---

## 二、事中转换：鲁棒的参数适配层

即使 LLM 生成的值不完全符合 schema，也可以通过适配层进行智能转换，而不是直接报错。

### 1. 类型强制转换（Safe Casting）
对基础类型，编写安全转换函数：

```python
def coerce_value(value, expected_type):
    if expected_type == "number":
        if isinstance(value, (int, float)):
            return value
        if isinstance(value, str):
            # 尝试解析数字
            try:
                return float(value)
            except ValueError:
                return None   # 转换失败
    if expected_type == "integer":
        if isinstance(value, int):
            return value
        if isinstance(value, str) and value.isdigit():
            return int(value)
    # 布尔值：识别 "yes"/"true"/"1"
    if expected_type == "boolean":
        if isinstance(value, bool):
            return value
        if isinstance(value, str):
            return value.lower() in ("true", "yes", "1")
    return value  # 默认返回原值
```

### 2. 日期/时间归一化（使用解析库）
日期表达最易产生歧义。引入 `dateparser` 或 `chrono` 等库，将自然语言转为标准格式。

```python
import dateparser

def normalize_date(date_str):
    # 输入: "tomorrow", "next Monday", "2025-04-11"
    parsed = dateparser.parse(date_str, settings={'PREFER_DATES_FROM': 'future'})
    if parsed:
        return parsed.date().isoformat()  # YYYY-MM-DD
    return None   # 无法解析则返回空，交给 LLM 重试
```

### 3. 枚举值模糊匹配
当 LLM 输出的枚举值大小写、缩写或近义词不匹配时，进行模糊映射。

```python
def match_enum(value, allowed_values):
    value_lower = value.lower()
    # 精确匹配
    for allowed in allowed_values:
        if allowed.lower() == value_lower:
            return allowed
    # 别名映射
    alias_map = {
        "c": "celsius", "cel": "celsius", "f": "fahrenheit", "fahr": "fahrenheit"
    }
    if value_lower in alias_map:
        return alias_map[value_lower]
    # 相似度匹配（Levenshtein）
    from difflib import get_close_matches
    matches = get_close_matches(value_lower, [v.lower() for v in allowed_values], n=1, cutoff=0.8)
    if matches:
        return allowed_values[[v.lower() for v in allowed_values].index(matches[0])]
    return None
```

### 4. 缺失必填参数的智能补全
如果 LLM 漏掉了必填参数，可以从对话历史、用户上下文或默认值中尝试补全。

```python
def fill_missing_params(schema, arguments, context):
    for required in schema.get("required", []):
        if required not in arguments:
            # 从 context 中查找（例如用户之前提到的城市）
            if required == "city" and context.get("current_city"):
                arguments[required] = context["current_city"]
            # 使用 schema 中的 default
            elif "default" in schema["properties"].get(required, {}):
                arguments[required] = schema["properties"][required]["default"]
    return arguments
```

## 三、事后反馈：让 LLM 自我修正

如果经过上述转换仍然失败（例如日期解析返回 `None`），应将**明确的错误信息**返回给 LLM，让它重新生成正确的参数。

### 1. 返回结构化错误，指明问题字段
不要只返回 `"参数错误"`，而要具体到哪个字段、期望什么格式。

```python
{
  "error": true,
  "type": "param_conversion",
  "field": "date",
  "message": "无法解析日期 'tomorrow'，请使用 YYYY-MM-DD 格式，例如 2025-04-11"
}
```

### 2. 在 prompt 中教会 LLM 从错误中学习
在 system prompt 中加入指令：
> 当你收到工具的 `param_conversion` 错误时，请根据错误信息中的示例，修正对应参数的值，然后重新调用该工具。不要重复相同的错误。

### 3. 限制修正次数
避免 LLM 反复使用同样的错误参数。设置最多 2 次参数修正尝试，超过后放弃并告知用户。

## 四、工程实践建议

| 措施                           | 优先级 | 说明                                      |
| ------------------------------ | ------ | ----------------------------------------- |
| **严格 JSON Schema + 示例**    | 最高   | 从源头减少歧义，成本最低                  |
| **使用 structured output API** | 高     | 彻底杜绝格式错误（如 OpenAI strict mode） |
| **类型强制转换函数**           | 高     | 处理常见类型不匹配（字符串数字转数字）    |
| **日期解析库**                 | 中高   | 如果工具涉及日期，必加                    |
| **枚举模糊匹配**               | 中     | 根据枚举值数量决定是否实现                |
| **参数补全（默认值/上下文）**  | 中     | 提升用户体验                              |
| **错误反馈与重试**             | 高     | 兜底方案，必须实现                        |

**综合示例流程**：

```python
def prepare_arguments(tool, raw_args, context):
    # 1. 类型强制转换
    converted = {}
    for key, value in raw_args.items():
        expected_type = tool.schema["properties"].get(key, {}).get("type")
        converted[key] = coerce_value(value, expected_type)
    
    # 2. 日期归一化
    if "date" in converted and converted["date"]:
        parsed_date = normalize_date(converted["date"])
        if parsed_date:
            converted["date"] = parsed_date
        else:
            raise ParamConversionError("date", converted["date"])
    
    # 3. 枚举匹配
    for key, allowed in enum_constraints.items():
        if key in converted:
            matched = match_enum(converted[key], allowed)
            if matched:
                converted[key] = matched
            else:
                raise ParamConversionError(key, converted[key])
    
    # 4. 补全缺失参数
    converted = fill_missing_params(tool.schema, converted, context)
    
    # 5. 最终校验（使用 jsonschema）
    validate(converted, tool.schema)
    return converted
```

通过上述组合策略，参数提取与类型转换的歧义性问题可以降低 90% 以上，剩余少量无法转换的情况也会通过清晰的错误反馈快速解决。
