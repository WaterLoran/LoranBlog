# 工具调用的优先级与调度饥饿

在 Agent 系统中，**工具调用的优先级与调度饥饿**问题是指：当多个工具调用请求同时竞争有限资源（如线程池、数据库连接、外部 API 速率限制）时，如果某些高优先级任务持续到来，低优先级任务可能永远得不到执行，导致“饥饿”。尤其在 Agent 需要并行处理多个用户请求或复合任务时，饥饿会引发部分任务超时失败，影响用户体验和系统公平性。

下面从**问题根源**、**优先级设计**、**调度策略**、**防止饥饿的机制**以及**工程落地**五个方面展开。

---

## 一、问题根源

| 场景                         | 资源瓶颈            | 饥饿表现                                                     |
| ---------------------------- | ------------------- | ------------------------------------------------------------ |
| 高并发用户请求               | 线程池/协程槽位有限 | 某用户的低优先级任务被其他用户的高优先级任务无限阻塞         |
| 外部 API 限流（如 10 req/s） | 令牌桶容量          | Agent 内部的高优先级任务不断消耗令牌，低优先级任务永远排不上 |
| 共享数据库连接池             | 连接数上限          | 大量高优先级查询占满连接，低优先级写入任务等待超时           |
| 长时间运行的工具             | 执行线程            | 短任务被长任务阻塞（非饥饿，但类似）                         |

**核心原因**：默认调度器通常是 FIFO（先进先出）或随机，没有优先级区分，且缺乏老化（aging）机制。

---

## 二、优先级设计：如何定义任务优先级

优先级可以基于多个维度，并支持动态调整。

| 维度         | 示例                     | 优先级值（数字越小越高） |
| ------------ | ------------------------ | ------------------------ |
| 用户等级     | VIP 用户 > 普通用户      | VIP=1, 普通=10           |
| 任务类型     | 实时交互 > 后台批处理    | 实时=1, 批处理=20        |
| 任务依赖     | 处于关键路径上的步骤     | 关键路径=1, 非关键=5     |
| 剩余时间预算 | 即将超时的任务提升优先级 | 动态计算                 |
| 用户交互     | 等待用户确认后的下一步   | 人为提升                 |

在 Agent 中，可以在创建工具调用请求时附加一个 `priority` 字段，取值范围 0-100（0 最高）。

```json
{
  "tool": "send_email",
  "params": {...},
  "priority": 5,
  "user_id": "vip_123"
}
```

## 三、调度策略：优先级队列 + 资源感知

### 3.1 优先级队列（Priority Queue）

使用堆（heapq）或 `asyncio.PriorityQueue` 对请求排序，每次取优先级最高（数字最小）的任务执行。

```python
import asyncio
from heapq import heappush, heappop

class PriorityScheduler:
    def __init__(self, concurrency=5):
        self.queue = []          # 堆元素: (priority, seq, task)
        self.counter = 0         # 保证FIFO同优先级
        self.semaphore = asyncio.Semaphore(concurrency)

    async def submit(self, coro, priority=10):
        self.counter += 1
        heappush(self.queue, (priority, self.counter, coro))
        await self._schedule()

    async def _schedule(self):
        async with self.semaphore:
            if self.queue:
                _, _, coro = heappop(self.queue)
                await coro
```

### 3.2 多级队列（Multilevel Queue）

将不同优先级的任务放入不同的队列，每个队列拥有独立的资源配额。例如：
- 高优先级队列：专用 3 个线程
- 中优先级队列：专用 2 个线程
- 低优先级队列：共享 1 个线程

这样可以确保高优先级任务不被低优先级影响，同时低优先级也有资源执行。

### 3.3 资源感知调度

除了优先级，还要考虑任务对特定资源的消耗。例如：
- 调用同一外部 API 的任务应排队，避免超出速率限制。
- 可以按资源键（如 `api_name`）分队列，每个队列内部再按优先级排序。

```python
resource_queues = defaultdict(PriorityQueue)
# 提交时根据资源键放入对应队列
resource_queues[api_key].put((priority, task))
```

## 四、防止饥饿的机制

即使有优先级队列，如果高优先级任务源源不断，低优先级任务仍可能饥饿。需要引入**老化**（Aging）。

### 4.1 动态提升优先级

每当任务在队列中等待超过一定时间（如 5 秒），就将其优先级提高一级（数值减小）。最终低优先级任务会提升到足够高从而被调度。

**实现**：队列中存储 `(original_priority, enqueue_time, task)`，调度前计算动态优先级：

```python
def get_dynamic_priority(original_priority, wait_time_sec):
    # 每等待5秒，优先级提升10
    boost = (wait_time_sec // 5) * 10
    return max(0, original_priority - boost)
```

### 4.2 公平共享配额

为不同优先级分配**最低资源保证**。例如：
- 高优先级任务最多占用 70% 资源，低优先级至少 10% 资源。
- 使用带有权重的公平队列（如 Weighted Fair Queuing）。

### 4.3 抢占式调度（高级）

对于长时间运行的任务，可以在高优先级任务到来时暂停低优先级任务（如果工具支持暂停/恢复）。但在大多数工具调用中，抢占不现实（如 HTTP 请求无法中断）。通常不推荐。

### 4.4 超时与放弃

为每个任务设置最大等待时间（如 30 秒），超时则直接失败并返回错误，由 Agent 上层处理（如重试或降级）。这至少避免了无限饥饿。

## 五、工程落地建议

1. **选择合适的调度器**：
   - 单进程 Agent：使用 `asyncio.PriorityQueue` + 动态老化。
   - 分布式 Agent：使用 Redis 有序集合（Sorted Set）作为优先级队列，配合消费者组。

2. **定义优先级来源**：
   - 从用户请求头中提取 `X-Priority`。
   - 在 Agent 内部根据任务类型自动设置（例如，用户正在等待回复的步骤设为高优先级，后台摘要生成设为低优先级）。

3. **监控饥饿指标**：
   - 记录每个任务的 `wait_time`（从入队到开始执行的时间）。
   - 设置告警：若某个优先级等级的任务平均等待时间超过阈值（如 10 秒），说明可能存在饥饿。

4. **结合资源限流**：
   - 优先级调度器应与限流器（令牌桶）配合。高优先级任务可以获得更多令牌配额。

5. **测试**：
   - 编写压力测试，模拟高优先级任务持续涌入，验证低优先级任务最终是否被调度。

## 六、示例代码（简化版）

```python
import asyncio
import time
from heapq import heappush, heappop

class AgingPriorityQueue:
    def __init__(self):
        self._heap = []
        self._counter = 0

    def put(self, priority, task):
        self._counter += 1
        heappush(self._heap, (priority, self._counter, time.time(), task))

    def get(self):
        while self._heap:
            orig_prio, _, enqueue_time, task = heappop(self._heap)
            wait = time.time() - enqueue_time
            # 老化：每等待5秒，优先级提升10
            boosted_prio = max(0, orig_prio - int(wait // 5) * 10)
            # 如果提升后仍大于当前堆顶的优先级，需要重新插入（简化版：直接返回并记录）
            # 实际应重新入队，但这里演示直接返回
            return task, boosted_prio
        return None

# 调度器使用该队列，每次取优先级最高的任务
```

## 七、总结

解决工具调用的优先级与调度饥饿问题，核心是 **优先级队列 + 老化机制 + 资源配额保证**：

- **优先级队列**：确保高优先级任务先执行。
- **老化**：提升等待过久任务的优先级，防止饥饿。
- **资源分区**：为不同优先级分配独立资源池，保证低优先级也有执行机会。
- **超时放弃**：作为兜底，避免无限等待。

在 Agent 系统中，大多数场景下使用基于优先级的异步队列 + 动态老化即可满足需求。如果任务对资源有强依赖（如 API 限流），则需结合资源感知队列。通过监控等待时间，可以及时发现并调整调度策略。
