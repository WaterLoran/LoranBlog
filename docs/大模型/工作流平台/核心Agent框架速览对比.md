# 核心Agent框架速览对比

### 🤖 核心Agent框架速览对比

| 框架                  | 核心范式                           | 主要定位                              | 优点                                                         | 缺点                                                         | 擅长领域                                        |
| :-------------------- | :--------------------------------- | :------------------------------------ | :----------------------------------------------------------- | :----------------------------------------------------------- | :---------------------------------------------- |
| **LangGraph**         | 有向图状态机                       | 构建**有状态、可控制**的复杂多步Agent | 流程控制精准，状态管理强，支持人机协作，执行效率高[reference:2][reference:3] | 学习曲线陡峭，代码量大                                       | 长周期、逻辑复杂的任务，如深度研究助手          |
| **PydanticAI**        | 类型安全，数据验证                 | 生产级、**强类型**的Python Agent开发  | 开发体验极好，类型安全，高可靠性，IDE支持佳[reference:4][reference:5] | 生态较新，目前主要面向Python                                 | 对稳定性和数据校验要求严苛的Python后端服务      |
| **Semantic Kernel**   | 内核(Kernel) + 插件(Plugins)       | 微软生态的**企业级AI应用编排**        | 企业级工程化强，多语言支持（C#/Python/Java），已演进为MAF[reference:6][reference:7] | 概念较重，早期Python生态不够成熟                             | 微软技术栈企业、需要严格安全合规的场景          |
| **CrewAI**            | 角色扮演，团队协作                 | **最快实现**的多Agent原型开发         | 上手极快，团队协作概念直观，生态庞大[reference:8][reference:9] | 资源消耗高，流程黑盒，生产化困难[reference:10][reference:11] | 快速验证、内容生成、调研分析                    |
| **AutoGen (MAF)**     | 对话式多Agent协作                  | 构建**对话驱动**的智能应用            | 对话式协作灵活，消息驱动，与微软生态深度融合[reference:12][reference:13] | 流程可控性弱，有过“衰落”传闻[reference:14]                   | 需要多角色讨论、协商的应用场景                  |
| **LlamaIndex**        | 数据索引与检索                     | **数据为中心**的RAG与Agent开发        | 数据连接器丰富，索引策略强大，RAG能力顶尖[reference:15][reference:16] | Agent编排能力相对弱，已和LangGraph融合                       | RAG（检索增强生成）和数据密集型应用             |
| **DSPy**              | 声明式编程，自动优化               | **系统化**的LLM程序优化               | 摒弃手写提示词，通过编译优化提高模型表现[reference:17]       | 学习曲线陡峭，概念前卫，社区“叫好不叫座”[reference:18]       | 需要系统化、自动化优化LLM提示词和推理流程的场景 |
| **TaskWeaver**        | 代码优先，计划-执行                | 面向**复杂数据分析**任务的Agent       | 自然语言转代码，丰富数据结构支持，灵活[reference:19][reference:20] | 定位较垂直，通用性不如其他框架                               | 数据分析、数据科学领域                          |
| **Haystack**          | 管道式管道                         | **生产级RAG和搜索系统**构建           | 模块化管道，生产就绪，企业级支持[reference:21]               | Agent编排能力弱于LangGraph等                                 | 构建企业级RAG、问答和语义搜索应用               |
| **Rasa**              | 意图识别 + 对话管理                | **对话式AI**平台，企业级聊天机器人    | 开源可控，深度定制，企业级安全[reference:22]                 | 需要ML知识，维护成本高                                       | 需要私有化部署、高度定制的企业级客服、对话系统  |
| **Strands Agents**    | 模型驱动，运行时决策               | AWS生态的**轻量级**Agent开发          | 低代码，与AWS深度整合，已用于Amazon Q Developer[reference:23][reference:24] | 与AWS绑定较紧                                                | AWS云原生应用、Serverless Agent部署             |
| **Deep Agents**       | 子Agent (Subagents) + 技能(Skills) | 解决**上下文膨胀**，构建长周期任务    | 有效隔离上下文，支持并行，内置通用子Agent[reference:25]      | 增加系统复杂度，本质是LangGraph模式                          | 长上下文、需要大量工具调用的复杂任务            |
| **Flowise**           | 可视化拖拽                         | **低代码/无代码**LLM应用构建          | 无需编码，上手快，适合快速原型验证[reference:26]             | 灵活性受限，不适合复杂生产系统                               | 非技术背景人员快速构建AI应用原型                |
| **Dify**              | 可视化工作流                       | 开源LLM应用开发平台                   | 可视化工作流，RAG能力强大，支持私有化部署[reference:27]      | 复杂流程编排能力弱于LangGraph                                | 团队快速构建RAG应用、内部AI工具                 |
| **AutoGPT / BabyAGI** | 自主循环，任务拆解                 | 早期**自主Agent**探索                 | 概念引领，展现了自主可能性[reference:28]                     | 热度消退，不成熟，易陷入循环[reference:29][reference:30]     | 实验性项目，探索AI自主性边界                    |
| **SuperAGI**          | 自主多Agent                        | 构建**高自主性**的Agent               | 强调自主操作，Agent可长期运行[reference:31]                  | 成熟度待考证                                                 | 希望Agent能高度自主完成复杂业务目标的场景       |
| **MetaGPT**           | 模拟软件开发团队                   | 将软件开发流程**标准化**              | 模拟软件公司流程，产出规范[reference:32]                     | 流程较固定，灵活性不足                                       | 自动化软件开发、生成标准文档和代码              |
| **OpenClaw**          | 操作系统集成                       | 让AI获得**“动手”能力**                | 可操作电脑，执行实际任务，体验震撼[reference:33][reference:34] | 安全风险极高                                                 | 需要AI操控电脑、浏览器等本地应用的个人助理      |
| **AgentScope**        | 模块化多智能体                     | **Java生态**的生产级多Agent开发       | 面向Java开发者，模块化，支持大规模Agent[reference:35]        | 生态新，主要面向Java                                         | Java技术栈团队构建企业级多Agent系统             |

### 💡 怎么选？一张决策表帮你快速定位

| 如果你...                                                  | 那么优先考虑...                |
| :--------------------------------------------------------- | :----------------------------- |
| 追求极致的**流程可控性和状态管理**                         | **LangGraph**                  |
| 是**Python开发者**，且把**类型安全和生产稳定性**放在首位   | **PydanticAI**                 |
| 团队深度使用**微软技术栈**（.NET, Azure）                  | **Semantic Kernel (MAF)**      |
| 需要**最快速度**做出一个多Agent演示原型                    | **CrewAI**                     |
| 主要做**RAG应用**，希望数据检索部分做到极致                | **LlamaIndex**                 |
| 想用**可视化的方式**快速构建AI应用，不写或写少量代码       | **Dify**（推荐）或 **Flowise** |
| 要开发一个**高度定制化**、可私有部署的企业级**对话机器人** | **Rasa**                       |
| 你的应用深度绑定**AWS**，追求Serverless部署                | **Strands Agents**             |

除了框架本身，**ReWOO 模式**也是一种重要的思考方式，尤其适合工具调用多、需要规划后执行的场景[reference:36]。而像**Deep Agents、OpenClaw**这类前沿模式，则更适合在需要特定能力时，作为LangGraph等基础框架的补充或拓展。
