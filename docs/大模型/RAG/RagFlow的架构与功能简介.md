# RagFlow的架构与功能简介

RAGFlow 是一款开源的 RAG（检索增强生成）引擎，核心特色是**深度文档理解**和**可视化编排**。它不止是简单的知识库问答，更像是一个企业级的 RAG 操作系统。

---

## 一、系统架构

RAGFlow 采用**微服务模块化架构**，各组件各司其职，既保证性能又便于扩展：

```
┌─────────────────────────────────────────────────────────────┐
│                      用户层                                  │
│          Web UI  │  RESTful API  │  OpenAI 兼容接口          │
├─────────────────────────────────────────────────────────────┤
│                      应用层                                  │
│   聊天应用  │  智能体编排  │  知识库管理  │  数据流管道        │
├─────────────────────────────────────────────────────────────┤
│                      核心服务层                              │
│  深度文档理解  │  检索服务  │  重排序  │  生成服务            │
├─────────────────────────────────────────────────────────────┤
│                      存储层                                  │
│  向量数据库(ES/Infinity)  │  关系数据库(MySQL)  │  对象存储    │
└─────────────────────────────────────────────────────────────┘
```

### 核心组件

| 组件                       | 作用           | 说明                                       |
| -------------------------- | -------------- | ------------------------------------------ |
| **RAGFlow Core**           | 主应用服务     | 处理API请求、工作流编排、用户管理          |
| **MySQL**                  | 元数据存储     | 存储用户信息、知识库配置、对话记录         |
| **Elasticsearch/Infinity** | 向量检索引擎   | 存储文档向量、执行相似度检索，支持混合检索 |
| **MinIO**                  | 对象存储       | 存放原始上传文件（可选）                   |
| **Redis**                  | 缓存与任务队列 | 加速检索、处理异步任务                     |

**硬件要求**：4核CPU、16GB内存、50GB磁盘（Docker部署推荐配置）

## 二、核心功能详解

### 1. 深度文档理解（Deep Document Understanding）

这是 RAGFlow 最核心的差异化优势，解决了传统 RAG 解析复杂文档时内容丢失的问题。

- **多格式支持**：PDF、DOCX、PPT、Excel、图片、Markdown、HTML、JSON、EML 等十余种格式
- **智能解析**：通过视觉处理技术识别文档布局（标题/段落/换行），完整解析复杂表格（包括合并单元格、无边框表格）
- **多切片模板**：内置 General、Q&A、Resume、Paper、Table、Book、Laws 等12种预设切片方法，可按场景灵活选择
- **可视化干预**：支持查看每个切片的解析结果，发现错误可手动修改，确保知识库质量

### 2. 知识库（数据集）管理

- **多数据源同步**（v0.22.0+）：支持从 AWS S3、Google Drive、Notion、Confluence、Discord 等在线数据源自动同步
- **元数据过滤**：可为文档添加标签，检索时按条件过滤
- **增量更新**：支持文档级别的增删改查，无需全量重建
- **RAPTOR 支持**：支持对整个数据集或单文档构建树状摘要索引

### 3. 混合检索策略

RAGFlow 采用“多路召回 + 融合重排序”机制：

| 层级                 | 技术                   | 作用                              |
| -------------------- | ---------------------- | --------------------------------- |
| **精确匹配**         | BM25 / TF-IDF          | 处理关键词明确的查询              |
| **语义检索**         | 向量相似度（FAISS/ES） | 理解查询意图，召回语义相关内容    |
| **重排序（Rerank）** | 交叉编码器模型         | 对初筛结果重新排序，提升Top-K精度 |

支持用户调节**相似度阈值**和**关键词权重**，灵活平衡召回率与准确率。

### 4. 智能体（Agent）编排（v0.19.0+）

RAGFlow 提供了**可视化无代码智能体编排框架**：

- **组件化开发**：内置工具调用、记忆管理、规划决策等21个预制组件
- **Code 组件**：支持在流程中嵌入 Python/JavaScript 脚本，实现自定义数据处理
- **变量聚合器**（v0.22.0）：支持数据运算与会话变量定义
- **结构化输出**：Agent 可返回 JSON 格式的标准化数据
- **多模板**：提供公司研究报告、股票分析、交互式代理等预设模板

### 5. 跨语言与多模态

| 能力           | 说明                                             | 版本    |
| -------------- | ------------------------------------------------ | ------- |
| **跨语言搜索** | 中文查询可检索英文文档，多语言混合知识库统一检索 | v0.19.0 |
| **图像直显**   | 检索结果中的图片直接渲染展示，支持“以文搜图”     | v0.19.0 |
| **多模态检索** | 集成 CLIP 等视觉编码器，支持图文双向检索         | v0.19.0 |

### 6. 可编排数据摄取管道（v0.21.0+）

新增可视化数据流设计器，可自定义从数据源到知识库的完整 ETL 流程：

- 支持在画布上拖拽组件构建数据清洗工作流
- 可复用官方模板快速搭建标准方案
- 支持 Docling、MinerU 等多种解析器

### 7. API 与集成

- **OpenAI 兼容接口**：可直接用 OpenAI SDK 调用 RAGFlow 的对话服务
- **RESTful API**：覆盖知识库、文档、检索、对话的全功能 API
- **嵌入集成**：支持通过 iframe 将问答应用嵌入网站，可接入钉钉、企业微信

## 三、与某场景的匹配度

回到你之前提到的场景——**Git 管理 md 文件，变更后自动更新向量库，通过 API 检索**：

| 需求        | RAGFlow 支持情况                              |
| ----------- | --------------------------------------------- |
| md 文件解析 | ✅ 原生支持 Markdown，保留标题层级和格式       |
| 增量更新    | ✅ 通过 API 支持文档级增删改，无需全量重建     |
| API 检索    | ✅ 提供 `/api/v1/retrieval` 接口，支持语义检索 |
| 自动化触发  | ✅ 可写脚本调用 API，集成到 Git Hook / CI      |
| 引用溯源    | ✅ 返回结果带来源文件和 chunk 位置             |

用 RAGFlow 实现这个场景，你只需：
1. Docker 一键部署
2. 创建知识库，配置好嵌入模型
3. 写一个同步脚本，在 Git 变更时调用上传/删除 API
4. Agent 应用调用检索 API 获取相关内容

相比完全自研，RAGFlow 帮你省掉了**分块策略调优、向量库运维、混合检索实现、解析器开发**这些复杂工作。如果你的核心价值在于 Agent 的业务逻辑而非 RAG 基础设施，它是个很合适的选择。
