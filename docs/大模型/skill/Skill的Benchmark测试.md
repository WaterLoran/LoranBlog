# Skill的Benchmark测试

对Skill进行Benchmark（基准测试），核心是**通过可重复、可量化的测试，来客观评估一个Skill对AI Agent的实际增益效果**。这能帮你回答“这个Skill真的有用吗？”以及“修改之后是变好了还是变坏了？”。

Benchmark的整体流程可以概括为三步：**编写Evals（评测用例） → 运行Benchmark（基准测试） → 分析报告与迭代**。

### 📝 第一步：编写Evals（评测用例）

Evals是Benchmark的基础，本质上是一组“考题”，用来检验Skill在特定输入下，是否能引导AI产生符合预期的输出。

*   **准备测试数据**：针对Skill的核心功能，设计一组能覆盖典型场景和边缘情况的Prompt（提示词）和对应的输入文件。
*   **定义“正确答案”**：为每个测试用例明确评判标准。这可以是一个确定性的结果（如“输出必须包含‘42’”），也可以是一组由评审模型（Judge Model）评估的定性标准。
*   **建议**：Evals最好能覆盖Skill的**主要功能路径**和**容易出错的边界情况**。

### 🚀 第二步：运行Benchmark（基准测试）

写好Evals后，就可以运行Benchmark了。核心方法是**对比测试（A/B Testing）**，以量化Skill的具体贡献。

*   **核心方法：有无对比（With/Without）**
    让AI在**加载Skill**和**不加载Skill（基线/Baseline）** 两种情况下，使用完全相同的Prompt，然后对比输出结果。净增益 = 有Skill的性能 - 无Skill的性能。

*   **主要工具与框架**
    *   **skill-creator (Anthropic)**：官方工具，内置Eval和Benchmark模式，可自动运行测试并记录通过率、耗时和Token用量等指标。
    *   **agent-skills-eval**：一个开源测试运行器，能自动执行“有无对比”测试，并由评审模型打分，生成并排对比报告。使用简单，一行命令即可入门。
    *   **SkillAudit**：端到端评估框架，能从**效用、效率/成本、安全性**等多个维度自动生成评估报告。
    *   **SkillsBench**：一个包含86个任务、横跨11个领域的综合性基准测试集，可用于在标准化的任务上评估Skill的表现。

*   **关键指标**
    运行Benchmark时，需要关注以下量化指标：
    *   **Eval通过率**：Skill帮助AI正确完成任务的百分比。
    *   **任务完成率/成功率**：在更复杂、端到端的任务中，Skill能帮助AI完成多少。
    *   **运行耗时**：加载Skill后，完成任务所需的时间。
    *   **Token使用量**：加载Skill会消耗额外的Token，需要权衡其带来的性能提升是否值得。

### 📊 第三步：分析报告与持续迭代

Benchmark运行完毕后，会生成详细的测试报告，这是你优化Skill的依据。

*   **解读报告**：分析在哪些测试用例上表现好，哪些失败了。特别注意**“无Skill”基线**的表现——如果基线已经能完美通过所有测试，说明这个Skill可能已经“过时”了。
*   **定位问题**：根据失败的用例，诊断是Skill的指令不够清晰，还是工作流有缺陷。
*   **迭代优化**：修改`SKILL.md`文件，然后**再次运行Benchmark**，对比前后两次的报告，确认修改是否带来了真正的提升。
*   **持续监控**：当AI模型或相关依赖更新后，重新运行Benchmark，以确保Skill在新环境下依然稳定有效。

### 💡 深入评估：超越“有用/没用”

除了基础的“有无对比”，更深入的评估可以关注以下几个维度：

*   **可发现性 (Discoverability)**：`description`是否精准？这决定了Agent能否在正确的场景下触发该Skill。
*   **执行引导清晰度 (Clarity of Guidance)**：Skill的指令是否像一本清晰的操作手册，让AI知道每一步该做什么？
*   **工作流完整性 (Workflow Completeness)**：流程是否端到端？异常情况（如API超时）有无处理方案？
*   **领域知识密度 (Domain Knowledge Density)**：Skill是否提供了AI本身不具备的领域知识？这是其价值所在。
*   **资源利用效率 (Resource Utilization)**：是否合理使用了脚本和参考文档，而不是把所有内容都塞进一个巨大的`SKILL.md`里？
*   **安全与成本 (Safety & Cost)**：Skill是否存在安全风险？其带来的收益是否值得额外的Token和时间成本？

### 💎 总结

给Skill做Benchmark，本质上就是用科学的方法，把“我感觉有用”变成“数据证明有用”。

**核心流程**：**编写Evals → 运行“有无对比”Benchmark → 分析报告并迭代**。

**核心工具**：可以关注`skill-creator`、`agent-skills-eval`、`SkillAudit`等。

**最终目标**：确保你的Skill不仅仅是“能跑”，而是真正**可靠、高效、有价值**的工具。
