AI领域的Skill，其内容格式是一个结构化的文件夹，核心是遵循 **Agent Skills 开放标准**。这个标准由 Anthropic 在 2025 年提出，目前已经被 Claude、OpenAI Codex、GitHub Copilot、Cursor 等主流平台广泛采用。

简单来说，一个标准的AI Skill文件夹就像一个小型的项目工程包，它通过特定的文件组织方式，让AI能够“理解”并“执行”一项专业任务。

### 📁 Skill 的核心文件结构

一个标准的Skill文件夹通常包含以下内容，其中 `SKILL.md` 是唯一必需的文件：

```text
your-skill-name/          # 文件夹名称就是技能的名字
├── SKILL.md              # (必需) 核心指令文件，包含元数据和操作指南
├── scripts/              # (可选) 存放可执行的代码脚本 (如 Python, Bash)
├── references/           # (可选) 存放参考文档，供AI按需查阅 (如 Markdown, txt)
└── assets/               # (可选) 存放资源文件，用于AI生成的输出中 (如图片、模板)
```

### 📄 SKILL.md：技能的操作手册

这个Markdown文件是Skill的灵魂，它分为两个部分：

1.  **元数据 (YAML Frontmatter)**：文件开头的 `---` 包裹区域，是给AI看的“技能名片”。
    *   `name` (必需): 技能的唯一ID，建议用小写字母和连字符，例如 `pdf-processor`。
    *   `description` (必需): **这是整个Skill中最重要的部分**。需要用一句话清晰、具体地描述技能的用途和触发场景。AI就是通过扫描这个描述来决定何时调用该技能的，所以必须包含精准的关键词。例如：“当用户需要从PDF文件中提取、修改或合并页面时使用此技能”。
    *   `allowed-tools` (可选): 指定该技能可以使用的工具，用于权限控制。

2.  **指令主体 (Markdown正文)**：这是给AI看的“操作手册”。需要用清晰、指令性的语言，一步步告诉AI如何完成这项任务。例如，可以定义工作流程、数据处理规则、输出格式要求，并说明如何调用 `scripts/` 文件夹中的脚本。

**一个完整的 `SKILL.md` 示例** (PDF处理技能)：
```markdown
---
name: pdf-processor
description: 从PDF文件中提取文本、合并多个PDF或旋转页面。当用户请求处理PDF文档时使用。
allowed-tools: [python, shell]
---

# PDF 处理技能

## 工作流程
1.  **理解用户请求**：判断用户是需要提取文本、合并PDF还是旋转页面。
2.  **调用相应脚本**：
    *   如需**提取文本**，运行 `python scripts/pdf_extractor.py --file_path <PDF路径>`。
    *   如需**旋转页面**，运行 `python scripts/pdf_rotator.py --file_path <PDF路径> --degrees 90`。
3.  **处理输出**：脚本执行后会返回一个JSON对象，包含操作结果和文件路径。
4.  **返回结果**：将处理结果用清晰的语言告诉用户。如果失败，请提供脚本返回的错误信息。

## 规则与指南
*   在处理前，始终检查PDF文件是否存在。
*   如果文件有密码保护，请礼貌地提示用户提供密码。
*   对于超过100页的大型PDF，提醒用户处理可能需要一些时间。
```

### 📦 打包资源 (可选)：技能的“工具箱”

这些文件夹不是必需的，但能让技能更强大：

*   **`scripts/` (脚本)**：存放可执行代码，用于需要高确定性的任务。例如，`scripts/parse_pdf.py` 可以是一个专门用来解析PDF的Python脚本，AI会按 `SKILL.md` 中的指示来运行它。
*   **`references/` (参考)**：存放供AI查阅的文档，如公司API设计规范、数据库架构说明、专业术语表等。这样做的好处是保持 `SKILL.md` 本身简洁，只在需要时才加载这些长篇文档。
*   **`assets/` (资源)**：存放AI在生成最终输出时要使用的文件，比如公司Logo、PPT模板、HTML邮件样板等。AI不会“阅读”这些文件的内容，而是直接把它们作为成品的一部分提供给用户。

### ⚙️ 核心机制：渐进式披露 (Progressive Disclosure)

Skill之所以高效，核心在于其“渐进式披露”的设计原则，这能有效避免给AI的“上下文”一次性塞入太多信息，导致其“思维混乱”或成本飙升。整个过程分为三个层次：

1.  **元数据层**：在AI启动或对话开始时，只加载所有Skill的 `name` 和 `description`，占据极少上下文。
2.  **技能主体层**：当AI根据 `description` 判断某个任务需要特定技能时，才会去读取对应 `SKILL.md` 文件的完整内容。
3.  **资源层**：在执行任务过程中，如果AI发现需要查阅更详细的参考资料或运行脚本，它会按需去 `references/` 或 `scripts/` 文件夹中加载具体文件。

```mermaid
flowchart LR
    A[用户提出请求] --> B{AI扫描所有<br>Skill的元数据<br>(name & description)};
    
    B -- 根据描述匹配 --> C[找到最相关的Skill];
    
    C --> D[AI加载该Skill的<br>完整 SKILL.md 文件];
    
    D --> E{执行任务过程中<br>是否需要更多信息？};
    
    E -- 是，需要参考文档 --> F[从 references/ 加载];
    E -- 是，需要执行代码 --> G[调用 scripts/ 中的脚本];
    E -- 否 --> H[完成任务，生成回复];
    
    F --> H;
    G --> H;
```

### ✍️ 编写高效Skill的最佳实践

*   **描述要精准**：`description` 是路由的关键，要像写搜索引擎的关键词一样，确保AI能准确匹配到它。
*   **指令要具体**：使用动词开头的祈使句，如“提取文本”、“合并文件”，而不是模棱两可的描述。
*   **遵循“懒加载”**：把长文档、大段说明放到 `references/` 里，只在 `SKILL.md` 中引用它们，保持核心文件简洁。
*   **单一职责**：一个Skill只做一件事，并把它做好。复杂的任务可以由多个Skill像乐高一样组合完成。
