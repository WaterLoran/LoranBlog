# 知识库软件资产

---

### 一、全局入口：智能搜索框（最高频组件）
- **呈现形式**：页面顶部的全局搜索（类似Elasticsearch），支持**模糊匹配 + 标签联想**。
- **交互效果**：输入“锁库”，下拉菜单不仅显示术语定义，还会直接带出**关联的流程图节点**和**规则卡片**，用户不用翻目录，直接一步直达。

---

### 二、术语与词典 → “知识卡片 + 关系标签云”
- **呈现形式**：不再是大表格，而是**瀑布流卡片**。每张卡片顶部是术语（如 `SKU`），正文是定义。
- **核心交互**：卡片底部带有**关联标签（Chips）**，例如 `#商品实体`、`#库存规则`。点击标签，页面右侧滑出“关系图谱”，显示该术语在哪些流程节点、哪些字段中被引用。

---

### 三、数据字典 → “ER图画布 + 字段侧边栏抽屉”
- **呈现形式**：**可拖拽缩放的ER图（实体关系图）**，用圆形代表`User`，菱形代表`Order`，连线代表外键。
- **核心交互**：点击图上的任意表（如 `order`），**右侧抽屉**滑出，展示该表的所有字段列表（字段名、类型、枚举值）。枚举值（如 `10-待支付`）会渲染成**彩色徽章（Badge）**，鼠标悬停显示状态流转条件。

---

### 四、业务流程 → “高亮可点的状态机/泳道图”
- **呈现形式**：绘制**BPMN流程图**或**状态机转移图**。节点用不同颜色区分（绿色-终态，黄色-等待中，红色-异常回滚）。
- **核心交互（杀手级）**：**点击任意节点**（比如“支付回调”节点），页面不会跳转，而是**原地弹窗/底部面板**浮出该节点挂载的所有**业务规则（R-ORDER-XXX）**和**涉及的数据字段**。用户看流程的同时，把背后的规则也吃透了。

---

### 五、业务规则 → “结构化决策表 + 自然语言生成”
- **呈现形式**：极度排斥“纯文本段落”。规则会渲染为两种形态：
  1. **决策表（Decision Table）**：用类似Excel的网格，列是“条件（IF）”，列尾是“结果（THEN）”，一目了然。
  2. **规则可视化卡片**：针对复杂逻辑，系统自动将伪代码渲染成**“If-Then-Else”折叠块**。
- **核心交互**：每条规则右上角都有一个 **“影响分析”** 按钮，点击后生成一个微型拓扑图，显示这条规则改了，会牵连哪几个流程、哪几张表。

---

### 六、角色与权限矩阵 → “热力矩阵 + 角色模拟器”
- **呈现形式**：这是一个**带颜色深浅的热力图（Heatmap）**。横轴是“功能模块”，纵轴是“角色”，交叉点用 ✅ / ❌ / ⚠️ 表示，且用**红绿灯颜色**区分。
- **核心交互（高阶）**：提供一个 **“角色模拟器（Impersonator）”** 开关。我在页面上切换成“客服”角色，整个页面的数据字典会**自动置灰/隐藏**敏感字段（如手机号），让权限规则变得可“感知”。

---

### 七、非功能约束与合规 → “仪表盘（Dashboard）指标卡”
- **呈现形式**：这类数字指标（响应时间<150ms，QPS 1w+）不放在文章里，而是做成**实时/准实时的仪表盘小部件（Widget）**，放在流程图的侧边。
- **核心交互**：当流程图中的节点（如“下单接口”）当前监控指标超标时，该节点会自动**闪烁红框**，并链接到对应的SLA约束文档。

---

### 八、关系联动导航（元模型落地） → “知识图谱（Graph Network）”
- **呈现形式**：这是软件页面**区别于文档的灵魂组件**。整个页面右侧或底部有一个**力导向关系图（Force-directed graph）**，像一张星云网。
- **核心交互**：我在页面主内容区看“优惠券规则”，这张关系网就自动高亮显示：`[优惠券规则]` ——关联——> `[Order.discount_amount字段]` ——关联——> `[提交订单流程节点]`。用户可以拖拽这个网，发现隐藏的依赖路径。

---

### 九、变更影响面分析 → “时间轴 + 依赖树（Dependency Tree）”
- **呈现形式**：当架构师想修改“拆单逻辑”时，页面提供一个 **“变更沙箱”**。
- **核心交互**：输入拟修改的资产（如 `拆单规则`），系统自动渲染一棵**倒置的树状图**，树根是改动点，树枝向上蔓延，显示出“会影响 3个微服务、2张表结构、1个前端页面”。这比开会高效十倍。

---

### 十、整体页面布局（信息架构 IA）
一个好的业务知识库软件页面，通常采用 **“三栏式布局”**：

| 区域                   | 放置内容                                                     |
| :--------------------- | :----------------------------------------------------------- |
| **左侧窄栏（导航）**   | 6大维度的分类树（术语/数据/流程/规则/权限/约束），可折叠。   |
| **中间主区域（核心）** | 根据资产类型动态渲染（即上面1-7点，流程就渲染流程图，规则就渲染决策表）。 |
| **右侧边栏（上下文）** | **“此处发生了什么”**。无论中间看什么，右侧都固定显示：<br>1. 该资产的元数据（创建人/更新时间）。<br>2. **关联资产列表**（该规则被3个流程引用）。<br>3. 评论/答疑区（业务留痕）。 |

### 附加：极简 MVP（最小可行性）实现建议
如果你的团队暂时没资源做这么复杂的定制化系统，**强烈建议不要从零开发**，直接用现成工具组合：

1. **Notion + 数据库(DB)**：利用Notion的Relation（关联）和Rollup（汇总）功能，可以把“规则”和“流程”做成双向关联的卡片，自带图谱预览。
2. **Backstage（Spotify开源）**：如果你们是微服务架构，Backstage的TechDocs插件天然支持Mermaid渲染，能把流程图直接嵌进Markdown里，且带搜索。
3. **Confluence + 插件（Gliffy / Refined Theme）**：可以用Refined Theme的“内容导航面板”实现右侧关联推荐。

---

**总结一句话**：在软件页面上，**“术语”变成了可点击的标签，“流程”变成了可点节点的地图，“规则”变成了可筛选的决策表，“关系”变成了可拖拽的星云图**。
