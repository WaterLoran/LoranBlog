# DOM演变模板分类及详情

 **DOM 演变模板** 中的 **变更节点**，我们需要枚举出所有原子状态变化的类型（即“演变情况”）。这些情况由 **触发器** 和 **DOM 变化** 组合定义，涵盖用户在页面上的各种操作以及系统（网络、定时器、浏览器事件）引发的响应。

以下基于你提供的“用户操作→页面变化”通俗版，并补充常见的前端交互场景，归纳出一套完整的 **演变情况分类表**。每一条都可以直接映射到一个变更节点。

---

## 一、触发器分类

触发器分为三大类：
- **用户动作**（点击、输入、滚动、键盘、手势等）
- **网络响应**（请求成功、失败、超时）
- **系统/浏览器事件**（定时器、页面可见性变化、窗口尺寸变化、历史导航等）

---

## 二、DOM 变化类型分类

- **文本变化**：某个元素的 `innerText`/`textContent` 改变（如状态文字、计数）。
- **属性变化**：元素的 `class`、`style`、`disabled`、`src`、`data-*` 等属性变化。
- **结构变化**：增/删/移 DOM 节点（如新弹窗、列表追加、加载指示器出现/消失）。
- **无直接 DOM 变化**：仅触发后续异步流程或纯视觉反馈（如按钮涟漪动画），但业务状态未变。
- **整体页面替换**：整页刷新或导航到新 URL（此时所有 DOM 被销毁重建）。
- **视口/滚动变化**：滚动位置、元素进入可视区（通常不改变 DOM 内容）。
- **样式变化**：仅 CSS 类变化导致外观改变，不影响结构和文本（可归入属性变化）。

## 四、补充说明

- **复合节点**：一次用户操作可能同时触发多个原子变化（如点击提交按钮 → 按钮变为 disabled（属性变化） → 显示 loading 图标（结构变化） → 请求成功后显示成功提示（文本变化））。这些应拆分为多个节点，严格按顺序排列。
- **无变化节点**：某些操作（如点击只埋点的按钮）在业务上无 DOM 变化，但作为演变模板的起点仍可保留为一个节点（触发器类型明确，变化为空）。这样有助于完整追踪用户意图。
- **条件分支**：同一触发器可能因状态不同导致不同变化（如已登录/未登录点击“收藏”）。这时需要建模为不同演变模板，或在节点中增加前置条件判断。

以上枚举覆盖了前端页面中常见的 30 种原子演变情况。实际使用时，可根据具体业务场景增删或细化，但建议保持“触发器 + DOM 变化类型”的二元原子性，避免将多个逻辑合并。
