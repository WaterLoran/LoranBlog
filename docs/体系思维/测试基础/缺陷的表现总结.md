# 缺陷的表现总结



# 一、表象与行为层面缺陷（可直接通过对比“预期”发现）

这类缺陷通常在执行某个操作后立刻被看到或感知到，不需要深入分析数据或日志。

## 1.1 界面显示与交互缺陷
- **UI 布局错乱**：元素位置、大小、对齐与设计稿不符（如按钮偏移、文字截断、图片拉伸）
- **样式错误**：颜色、字体、间距、圆角、阴影等 CSS 属性与设计不符
- **控件状态错误**：按钮应禁用时可用、复选框应选中时未选中、下拉框选项缺失或重复
- **焦点管理错误**：弹窗打开后焦点不在输入框、Tab 键顺序错乱、回车键无响应
- **动画与过渡异常**：动画卡顿、跳帧、未按预期触发、结束时状态错误
- **响应式布局失效**：在不同分辨率、缩放比例下内容重叠或消失
- **本地化/多语言缺陷**：文本硬编码未翻译、占位符未替换、日期/数字格式不符合区域习惯

## 1.2 功能行为与需求不符
- **正向流程缺失或错误**：用户按正常步骤操作，无法完成核心功能（如提交订单失败、注册收不到验证码）
- **逆向流程处理错误**：取消、回退、删除等操作未按需求执行（如取消订单后库存未释放）
- **条件分支遗漏**：某些输入条件下应执行的分支未执行（如 VIP 用户应免运费，实际仍收取）
- **计算或校验规则错误**：金额、折扣、积分等计算结果与需求公式不一致；输入校验（格式、长度、范围）与需求不符
- **数据展示错误**：展示的字段内容、格式、单位与需求不符（如日期显示为时间戳、价格缺少货币符号）
- **权限控制缺失或错误**：无权限用户能看到或操作本不应访问的功能；有权限用户反而无法操作

## 1.3 文案与提示错误
- **静态文案错误**：拼写错误、语法错误、术语不一致（同一功能在不同页面名称不同）
- **动态提示错误**：成功/失败提示内容与实际情况相反（如“保存成功”但数据未保存）
- **错误码与说明不匹配**：弹出“系统错误”但无具体错误码，或错误码对应的说明错误
- **占位符与变量替换错误**：提示中的用户名、订单号等变量显示为 `{name}` 或空值
- **确认对话框信息缺失**：删除确认未告知影响范围，危险操作无二次确认

## 1.4 报错与崩溃
- **应用崩溃**：闪退、ANR（应用无响应）、页面白屏、JS 引擎异常退出
- **未捕获的异常**：后端返回 500、前端控制台报 `Uncaught TypeError`、数据库死锁异常直接暴露给用户
- **无限加载或转圈**：操作后一直显示 loading，最终超时或无反馈
- **假死或卡死**：界面可点击但无任何响应，或整个页面无法滚动/点击

## 1.5 兼容性问题
- **浏览器兼容**：在 Chrome/Firefox/Safari/Edge 中行为或样式不一致
- **操作系统兼容**：Windows/macOS/iOS/Android 下表现不同（如文件选择器、右键菜单）
- **设备兼容**：不同屏幕尺寸、分辨率、DPI 下布局错乱；触摸与鼠标事件差异
- **第三方依赖兼容**：特定版本的库、API、浏览器插件导致功能失效

# 二、业务逻辑层面缺陷（规则与状态机错误）

这类缺陷在正常操作路径上可能不会立即报错，但业务规则被违反，导致系统行为不符合业务语义。

## 2.1 条件分支遗漏或错误
- **判定表未覆盖的组合**：例如“会员等级 + 商品类型 + 优惠券类型”的某些组合未写对应逻辑，返回默认/错误结果
- **条件优先级错误**：当多个条件同时满足时，应优先应用的规则未被应用（如“免运费”与“折扣”同时存在时计算顺序错误）
- **短路逻辑错误**：逻辑与/或的短路求值不符合预期（如 `if (user != null && user.isVip())` 中 `user` 为 null 时报错）

## 2.2 状态机非法迁移
- **允许了非法状态跳转**：如“已取消”的订单可以再次“确认收货”、“已退款”的订单可以再次“申请退款”
- **禁止了合法状态跳转**：如“待支付”状态下不能“取消订单”
- **状态迁移后遗漏副作用**：状态变为“已发货”后未触发物流推送、未扣减库存锁定
- **并发下的状态冲突**：同一订单同时被两个请求改为“已取消”和“已支付”，最终状态不一致

## 2.3 业务规则组合缺失
- **规则冲突**：两条规则同时触发时产生矛盾（如“满100减20”和“全场9折”同时生效时，折后满减顺序导致不同结果，需求未明确）
- **规则循环依赖**：A 规则触发后导致条件满足 B 规则，B 规则又触发 A 规则，造成无限循环或栈溢出
- **规则时效性错误**：规则应在活动结束后失效，但依然被应用；或活动开始前就被提前应用

## 2.4 逆断言失败（不该发生的事情发生了）
- **副作用重复执行**：用户点击一次，系统却发送了两条通知、扣了两次积分
- **不应该产生的数据被创建**：校验失败时依然生成了订单号；未付款时锁定了库存
- **不应该变化的数据被修改**：只读状态下用户不应修改字段，但通过工具或异常请求修改成功

## 2.5 模型输出与预期不一致（基于模型的测试）
- **业务规则引擎输出错误**：定价引擎、推荐引擎、风控引擎的输出与人工设计的真值表不符
- **状态机模型与实现行为不匹配**：使用模型生成的所有合法路径中，有一条在实际系统中执行结果不同

## 2.6 操作影响范围越界（副作用扩散）
- **权限粒度联动错误**：修改/收回细粒度权限时，错误地连带影响了粗粒度对象的可见性或可操作性（如收回责编的"CP书籍类型"权限后，CP选书页面连该责编原本可见的CP商都不再展示）
- **配置变更波及无关模块**：修改模块 A 的某项配置，导致模块 B 的展示或行为异常（如修改用户角色的"数据范围"后，与数据范围无关的菜单也被隐藏）
- **删除操作级联超出预期**：删除父级资源时，子级资源被正确级联删除，但关联的旁系资源（非父子关系）也被错误清除
- **状态变更影响无关联数据**：将某实体状态改为"禁用"后，与该实体仅有弱关联（如历史引用）的其他数据也受影响，表现为查询不出、不可操作
- **批量操作的影响范围超出选定目标**：批量修改 A 组数据，结果 B 组未被选中的数据也被修改
- **回收/降级操作未保留合理残留**：收回某项能力时，该能力已经产生的历史数据或已建立的关联应保留可见，但被一并清除

# 三、数据一致性层面缺陷（数据之间逻辑关系被破坏）

这类缺陷操作后表面可能提示成功，但数据库中数据之间的约束、汇总、关联出现了矛盾。

## 3.1 关联数据不匹配
- **父子表数据不一致**：订单表的 `总金额` 不等于订单明细表的 `金额之和`；账户表的 `余额` 不等于所有流水表的 `出入差额`
- **外键存在性缺失**：订单明细表中的 `商品ID` 在商品表中已删除；日志表中的 `用户ID` 对应用户已注销
- **冗余字段未同步**：用户昵称在用户表和评论表中不一致；库存表的 `可用库存` 与 `锁定库存+已售库存` 不符

## 3.2 冗余数据不一致
- **缓存与数据库不一致**：更新数据库后未淘汰或更新缓存，导致读取到旧数据
- **主从复制延迟导致不一致**：写入主库后立即从从库读取，读不到刚写入的数据（业务允许短暂不一致但未做容忍处理）
- **搜索引擎与数据库不一致**：商品信息更新后，ES 索引未更新，搜索仍展示旧内容
- **跨服务数据不一致**：订单服务调用库存服务扣减成功，但订单服务自身事务回滚，导致库存凭空减少

## 3.3 事务部分提交/回滚失败
- **一个业务操作横跨多个独立事务，中间失败后无补偿**：例如先扣库存（事务A），再生成订单（事务B），扣库存成功后生成订单失败，库存未回滚
- **使用 `@Transactional` 不当导致异常被吞没**：捕获异常后不抛出，事务未回滚但数据已部分更新
- **嵌套事务中 PROPAGATION_REQUIRES_NEW 导致外层回滚但内层已提交**：内层事务提交后外层失败，内层操作无法撤销

## 3.4 并发下脏读/幻读/丢失更新
- **脏读**：事务A读取了事务B未提交的中间数据，事务B回滚，事务A基于脏数据做了决策
- **不可重复读**：事务A内两次读取同一行数据，期间事务B修改并提交，两次读取结果不同
- **幻读**：事务A内两次范围查询，期间事务B插入了符合条件的新数据，导致第二次查询多出行
- **丢失更新**：两个事务同时读取同一余额，各自加上一定金额后写回，后写的覆盖先写的结果

## 3.5 数据对账失败（自动化校验）
- **源系统与目标系统数据不一致**：ETL 后报表数据与原明细表汇总值不符
- **日切对账不平**：今日期初余额 ≠ 昨日期末余额；交易流水借贷不平衡
- **离线与在线数据差异**：数据仓库与在线业务库的统计指标对不上

# 四、时序与竞态层面缺陷（操作顺序/时间窗口导致错误）

这类缺陷依赖执行顺序、延迟大小或时间交错，往往在并发或异步场景下暴露。

## 4.1 操作顺序依赖错误
- **未按正确顺序执行**：应“先校验后扣款”却先扣款后校验；应“先锁定库存再支付”却支付后才锁定
- **顺序假设被打破**：开发者假设A先于B执行，但在分布式环境或回调中可能相反
- **缺少顺序保障机制**：消息队列的乱序消费导致状态退回（如“已发货”消息比“已支付”先消费）

## 4.2 异步任务状态可见性错误
- **中间状态暴露给用户**：支付异步回调未完成时，用户查询订单显示“支付失败”，实际上最终成功
- **最终状态未收敛**：异步任务永远处于“处理中”，没有超时或失败机制
- **异步结果覆盖正确结果**：主流程已取消订单，但异步任务完成后又把订单改为成功

## 4.3 并发请求乱序处理
- **相同请求乱序到达**：请求1（加10元）、请求2（减5元），若请求2比请求1先到达并处理，最终余额错误
- **依赖外部系统的响应乱序**：两次调用同一个外部服务，第二次响应先返回，程序按先返回的结果处理，导致逻辑错乱

## 4.4 超时与重试导致状态混乱
- **超时后重试成功，但原请求也最终成功**：导致重复执行（见幂等问题）
- **超时后客户端认为失败，服务端实际成功**：用户看到失败提示后重试，产生重复数据
- **未设置合理超时时间**：默认超时过长，阻塞资源；或过短导致频繁误判失败

# 五、资源管理层面缺陷（系统能力被耗尽或泄漏）

这类缺陷通常需要长时间运行或高负载才能显现，可能导致系统不可用或性能剧烈下降。

## 5.1 内存泄漏
- **未释放的对象引用**：静态集合持有临时对象；监听器注册后未注销；ThreadLocal 未清理（尤其在池化线程中）
- **缓存无限增长**：没有设置最大大小或淘汰策略（LRU、TTL）
- **大对象频繁分配**：在循环中创建大量临时对象，导致频繁 GC，甚至 OOM
- **资源流未关闭**：文件流、网络流、JDBC 的 ResultSet 未在 finally 中关闭

## 5.2 连接池/线程池耗尽
- **连接未归还**：获取连接后未关闭（或异常时未关闭），导致连接池耗尽
- **线程池队列积压**：任务生产速度远大于消费速度，导致内存溢出或请求超时
- **线程池参数配置错误**：核心线程数过小、最大线程数过大、拒绝策略不当（如无限制队列导致 OOM）
- **数据库连接泄漏**：事务异常或提前返回导致 connection 未被释放

## 5.3 文件句柄未释放
- **打开文件未关闭**：日志文件、上传文件、临时文件处理完毕后未关闭，达到系统限制后无法打开新文件
- **文件锁定未释放**：操作完文件后未释放锁，导致其他进程无法读写或删除

## 5.4 缓存无淘汰策略导致 OOM
- **本地缓存无限增长**：使用 HashMap 作为缓存且不设置上限
- **缓存 key 动态生成且无边界**：如根据用户查询条件生成大量不同 key，最终撑爆内存

## 5.5 其他资源泄漏
- **信号量、锁未释放**：使用 Semaphore 或 ReentrantLock 在异常路径未释放，导致后续线程永久等待
- **定时任务未取消**：动态创建的 Timer 或 Schedule 未在组件销毁时取消，导致资源累积和意外执行

# 六、幂等与重复执行层面缺陷（同一操作多次执行副作用不同）

这类缺陷在分布式系统、消息队列、用户快速操作场景下极为常见。

## 6.1 网络重试导致重复副作用
- **重复扣款**：支付请求超时后客户端重试，服务端两次扣款成功
- **重复发货**：发货接口被重试两次，生成两个物流单号
- **重复发送通知**：邮件、短信、推送被多次发送

## 6.2 用户快速双击重复提交
- **前端未防抖/节流**：按钮连续点击发起多个相同请求
- **后端未做幂等校验**：第一个请求处理中，第二个请求创建了重复订单
- **页面刷新或后退再次提交**：用户提交后刷新页面，浏览器提示重复发送表单

## 6.3 消息重复消费
- **Kafka/RabbitMQ 客户端提交 offset 失败**：消息被重新推送，消费者重复处理
- **消费者处理成功后确认超时**：导致 broker 重新投递
- **批量消费中部分成功部分失败**：重试时已成功的消息再次被处理

## 6.4 唯一约束缺失或失效
- **数据库缺少唯一索引**：允许插入重复的业务唯一键（如订单号、请求流水号）
- **唯一键设计不合理**：使用时间戳到毫秒级，但高并发下仍可能重复
- **分布式唯一 ID 生成器 bug**：雪花算法时钟回拨导致 ID 重复

## 6.5 幂等实现缺陷
- **幂等检查与业务操作非原子**：先检查是否已处理，再执行插入，中间有并发窗口
- **幂等 key 生命周期错误**：key 失效太早导致重放攻击；失效太晚导致正常请求被拒绝
- **使用状态机作为幂等但状态流转错误**：例如“已支付”状态重复接收支付回调，应直接返回成功，却再次执行扣款逻辑

# 七、事务与隔离性层面缺陷（事务属性设置不当）

这类缺陷与数据库、分布式事务密切相关，导致数据不一致或系统性能问题。

## 7.1 事务边界过大或过小
- **过大**：事务内包含外部 HTTP 调用、大量计算、长时间锁表，导致死锁增多、连接池耗尽
- **过小**：一个业务操作被拆成多个独立事务，中间失败无补偿（见 3.3）
- **声明式事务位置错误**：`@Transactional` 加在 private 方法上无效；加在 Controller 层导致事务持续时间过长

## 7.2 隔离级别设置不当
- **Read Uncommitted**：读到脏数据，导致业务决策错误（如库存预扣）
- **Read Committed**：不可重复读导致同一事务内前后判断不一致（如先读库存后扣减，期间库存被另一事务减少）
- **Repeatable Read**：幻读导致范围操作错误（如统计订单数后插入新订单，导致统计依据失效）
- **Serializable**：并发性能极低，且容易产生死锁

## 7.3 事务内远程调用导致死锁或长等待
- **调用第三方 API 耗时过长**：数据库连接被持有，其他事务等待
- **远程调用后再次访问数据库**：如果远程调用失败，事务仍需回滚，但远程调用无法回滚（需要补偿）
- **分布式事务中本地事务与远程资源协调不当**：如 TCC 模式下的 Confirm/Cancel 未实现幂等

## 7.4 缺少补偿事务（Saga/事务性消息）
- **跨服务业务操作失败**：订单服务成功，库存服务失败，但订单未回滚，需要补偿（如取消订单）
- **消息发送与本地事务不一致**：本地事务提交成功，但消息未发送出去，其它服务未感知
- **本地事务回滚后消息已发出**：先发消息后提交事务，事务回滚导致虚假消息

## 7.5 事务超时与回滚逻辑错误
- **`@Transactional(timeout)` 未生效**：被嵌套事务覆盖；或者超时后不会自动回滚
- **非运行时异常不会回滚**：默认只对 `RuntimeException` 和 `Error` 回滚，检查型异常需配置
- **回滚后未重置序列或自增主键**：回滚后自增 ID 仍然增加，造成 ID 空洞（虽不错误，但可能引起预期外的行为）

---

# 八、异常处理与补偿层面缺陷（失败路径未被妥善管理）

这类缺陷在正常环境下不出现，只在依赖失败、网络故障、硬件异常时暴露。

## 8.1 依赖服务失败未回滚
- **调用支付网关失败**：本地订单状态改为“待支付”，但支付实际失败，用户看到待支付却无法成功
- **消息队列发送失败**：业务状态已提交，但无法通知下游系统，导致数据不一致
- **缓存写入失败**：写入数据库成功，但更新缓存失败，之后读取到旧数据

## 8.2 异常被吞没（空 catch 块）
- **`catch(Exception e) { }`**：不记录日志也不抛出，出错后继续执行，导致数据错误且无法定位
- **异常后继续执行关键逻辑**：扣款失败但依然发送成功通知
- **`finally` 块中抛出异常覆盖原始异常**：原始异常丢失，只看到 finally 中的异常

## 8.3 错误状态未记录或告警
- **失败后未记录错误日志**：运维无感知，问题长时间存在
- **未区分瞬时错误与永久错误**：所有错误都重试，导致最终无效
- **没有上报监控指标**：失败率、错误类型无法统计

## 8.4 补偿逻辑缺失或错误
- **缺少回滚操作**：取消订单时应释放优惠券、解锁库存，但未实现
- **补偿操作不幂等**：多次执行补偿（如重复释放库存）导致数据错误
- **补偿顺序错误**：应先释放优惠券再解锁库存，但顺序反了，优惠券释放失败时库存已解锁，无法回滚补偿
- **补偿超时未重试**：执行补偿时网络失败，没有重试机制，遗留脏数据

---

# 九、边界与溢出层面缺陷（极限值引发错误）

这类缺陷通常在输入或状态达到临界值时触发，常规测试难以覆盖。

## 9.1 数值溢出
- **整数溢出**：`int` 最大值加 1 变成负数；金额乘系数后超过 `Long.MAX_VALUE`
- **浮点数精度丢失**：使用 `float` 或 `double` 计算金额，0.1+0.2 结果不是 0.3
- **类型转换溢出**：`long` 强转为 `int` 截断高位；字符串转数字超出范围

## 9.2 字符串/集合长度超限
- **数据库字段截断**：插入字符串长度超过 `varchar(255)`，被自动截断或抛出异常
- **集合容量无上限**：用户可无限添加购物车商品，最终 OOM 或响应超慢
- **数组/列表越界**：`IndexOutOfBoundsException`，如获取第 0 个元素时集合为空

## 9.3 分页边界错误
- **页号超过总页数**：后端返回空数据或报错，前端展示空白
- **页号小于 1**：应默认第 1 页，但可能报错或返回奇怪数据
- **每页条数为 0 或负数**：导致 SQL 错误或死循环
- **总条数巨大时分页性能差**：`OFFSET 1000000` 导致数据库扫描大量数据

## 9.4 递归栈溢出
- **递归无终止条件**：目录遍历循环引用；组织架构上下级形成环
- **递归深度过大**：默认栈大小 512KB，深度几千就可能溢出
- **尾递归未优化**：语言或编译器不支持尾递归优化，导致栈溢出

## 9.5 边界条件未处理
- **空值/空集合**：`null` 传入方法导致 NPE；空列表求平均值抛出异常
- **零值除**：除数为 0 导致 `ArithmeticException`
- **单元素边界**：列表删除操作时，只有一个元素时能否正确删除
- **最大/最小日期**：`9999-12-31` 加一天；`1970-01-01` 之前的时间戳处理错误

# 十、非功能性层面缺陷（质量属性不达标）

这类缺陷不影响功能正确性，但影响用户体验、系统稳定性、安全性等。

## 10.1 性能问题
- **响应时间长**：接口平均耗时超过 SLA 约定（如 >200ms）
- **吞吐量低**：系统在预期并发下 TPS 不达标
- **资源占用过高**：CPU、内存、磁盘 IO 异常飙升
- **慢 SQL**：缺少索引、全表扫描、N+1 查询
- **前端性能差**：首屏加载慢、滚动卡顿、内存泄漏导致页面变慢

## 10.2 安全问题
- **注入漏洞**：SQL、NoSQL、OS 命令、LDAP 注入
- **跨站脚本 (XSS)**：未转义的用户输入被当作脚本执行
- **跨站请求伪造 (CSRF)**：未使用 token 或 Referer 校验
- **越权访问 (IDOR)**：用户 A 可通过修改资源 ID 访问用户 B 的数据
- **敏感信息泄露**：日志打印密码、身份证；前端源码暴露 API 密钥
- **认证与会话管理缺陷**：会话固定、弱密码策略、会话超时过长
- **文件上传漏洞**：上传可执行文件、路径遍历、大小无限制

## 10.3 兼容性问题
- **操作系统兼容**：Windows/Linux 下路径分隔符差异；macOS 中文件大小写不敏感导致问题
- **浏览器兼容**：CSS Grid 在 IE 中失效；ES6 语法在旧浏览器报错
- **屏幕尺寸/分辨率**：小屏幕下关键按钮被遮挡；大屏下字体过小
- **设备兼容**：触摸屏与鼠标悬停事件差异；iOS 中日期选择器行为不同

## 10.4 易用性与体验问题
- **信息架构混乱**：用户难以找到所需功能
- **操作路径过长**：完成核心任务需要多次点击或跳转
- **反馈缺失**：点击按钮后无任何 loading 或提示，用户不确定是否生效
- **错误提示模糊**：只显示“操作失败”，不告知具体原因或解决办法
- **无障碍缺陷**：缺少 ARIA 标签、键盘无法访问、对比度低
- **不符合用户心理模型**：删除操作没有撤销、刷新页面丢失表单数据

## 10.5 可靠性与可用性问题
- **单点故障**：关键服务无集群或备份，节点宕机后整体不可用
- **未实现重试与熔断**：依赖服务抖动时系统雪崩
- **日志与监控缺失**：无法排查问题，无法设置合理告警
- **数据备份与恢复**：无定期备份，或备份不可恢复

## 10.6 可维护性与可扩展性缺陷（代码层面）
- **硬编码**：配置、URL、密钥写在代码中
- **重复代码**：相同逻辑多处复制，修改时遗漏
- **高耦合**：修改一处需要改动多个模块
- **缺乏注释与文档**：复杂逻辑无人能看懂
