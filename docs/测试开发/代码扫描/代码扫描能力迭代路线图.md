# 代码扫描能力迭代路线图

---

## 代码扫描能力迭代路线图（测试平台集成）

### 阶段一：快速启动 —— 基础安全扫描能力集成（SAST + 基础SCA）

**目标**：在测试平台中快速上线代码静态分析（SAST）与依赖项漏洞扫描（SCA）能力，满足基本安全门禁需求。

**核心组件**：SonarQube + OWASP Dependency-Check

| 任务项             | 具体行动                                                     | 与测试平台集成方式                                           | 验收标准                                                     |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 搭建扫描引擎       | 部署 SonarQube 社区版，配置常用规则集（Java、Python、JS 等）；<br>部署 OWASP Dependency-Check 命令行或服务器版 | 平台通过 REST API 提交代码仓库 URL / 分支，触发扫描任务      | SonarQube 和 Dependency-Check 均能通过 API 返回结构化扫描报告（JSON/XML） |
| 实现扫描任务编排   | 开发平台内的“代码扫描”流水线步骤：拉取代码 → 调用 SonarQube 扫描 → 调用 Dependency-Check 扫描 → 汇总结果 | 平台后台服务封装两个工具的 API，统一处理认证、异步轮询、超时重试 | 一次扫描任务可在 10 分钟内完成（依代码量而定），平台能展示扫描进度 |
| 统一结果展示与门禁 | 设计扫描报告页面：展示代码异味、质量门状态、漏洞等级、CVE 列表；<br>定义阈值（如阻断高危漏洞 >0 或质量门失败） | 平台前端从后端获取扫描数据并渲染；质量门禁结果可转义为测试用例通过/失败 | 平台能够展示两种工具的合并报告，并根据阈值自动判定“代码扫描”测试项是否通过 |
| 基础 SCA 增强      | 配置 Dependency-Check 的 NVD API Key 及私有组件仓库（如企业 Maven/NPM 私服） | 平台允许用户在扫描配置中传入私有仓库认证信息                 | 可准确识别企业自研组件的已知漏洞                             |

**阶段一交付物**：
- 测试平台支持一键触发代码扫描（SAST+SCA）
- 扫描结果作为安全测试用例集成进测试报告中
- 支持质量门禁拦截（例如：阻止高危漏洞的构建继续）

---

### 阶段二：建立自定义壁垒 —— 灵活的规则引擎与门禁定制

**目标**：允许测试平台用户（开发、测试、安全人员）通过 Web 界面编写、管理自定义扫描规则，实现差异化的安全规范与代码风格门禁。

**核心组件**：Semgrep / Opengrep 或 Globstar（推荐 Semgrep，因其成熟生态和易集成性）

| 任务项               | 具体行动                                                     | 与测试平台集成方式                                           | 验收标准                                                     |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 引入自定义规则引擎   | 部署 Semgrep 引擎（可使用托管版或自托管），准备默认规则集，新增自定义规则存储库 | 平台后端在扫描流程中增加 Semgrep 调用，将其结果与阶段一结果合并 | Semgrep 能单独运行并输出 SARIF 或 JSON 结果，且可识别用户自定义的规则 |
| 可视化规则编辑器     | 开发 Web 前端：基于 Monaco Editor 的 YAML/规则语法编辑器，提供规则模板、语法高亮、在线测试（针对示例代码片段） | 平台前端通过 API 保存/更新规则至后端，后端将规则部署到 Semgrep 规则目录或通过配置引用 | 用户可在平台上创建一条规则（例如“禁止使用 eval”），并立即对该规则进行模拟扫描验证 |
| 规则版本管理与作用域 | 实现规则的版本历史、回滚、启用/禁用；支持将规则分配给特定项目或项目组 | 扫描任务启动时，平台根据项目 ID 动态组装规则集，传入 Semgrep | 不同项目可使用不同规则集；规则变更不影响正在运行的扫描任务   |
| 自定义质量门禁       | 允许用户定义规则触发的严重等级（阻断/警告/忽略），并可设置组合条件（例如：同时命中规则A和规则B才阻断） | 平台扫描后处理模块根据自定义门禁策略计算最终测试结果         | 用户可以配置“自定义规则命中超过 3 条则阻断”等复杂逻辑        |

**阶段二交付物**：
- 测试平台提供“自定义规则管理”模块，用户无需接触命令行即可编写、测试、发布扫描规则
- 支持项目级的规则差异化配置
- 自定义规则的结果与 SonarQube 结果一同显示，并纳入同一门禁系统

### 阶段三：走向深度与智能 —— 深度数据流分析 + AI 辅助审计

**目标**：解决通用规则无法发现的复杂漏洞（如跨函数数据流问题），并利用 AI 降低误报率、提供自动修复建议，形成深度防御体系。

**核心组件**：CodeQL + AI 代码审计工具（如 DeepAudit / 自研闭环模型）

| 任务项                   | 具体行动                                                     | 与测试平台集成方式                                           | 验收标准                                                     |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 集成 CodeQL              | 部署 CodeQL CLI，配置分析语言（Java、C#、Python、JS 等），准备标准查询库及自定义查询 | 平台将 CodeQL 作为扫描流水线中的一个可选深度分析阶段（用户可勾选），单独生成数据库并执行查询 | 能识别跨文件、跨函数的数据流漏洞（如 SQL 注入从入口点到执行点） |
| 优化性能与资源           | 对大型代码库实现增量分析或缓存数据库；支持异步执行并通知结果 | 平台提供“深度扫描”开关，开启后预估扫描时间并在完成后推送通知 | 深度扫描不阻塞其他测试任务，资源占用可控                     |
| AI 审计工具集成          | 接入开源或商业 AI 审计工具（如 DeepAudit），对扫描发现的潜在漏洞进行二次验证和解释 | 平台将前几个阶段的高危/可疑结果发送给 AI 工具，AI 返回漏洞置信度、修复建议；平台展示 AI 审计卡片 | AI 审计能降低误报率至少 30%，并能对部分漏洞生成可操作的代码修复建议 |
| 智能缺陷优先级排序       | 结合 AI 分析结果、漏洞可利用性、业务上下文（例如热点 API）计算风险分，自动推荐修复顺序 | 平台扫描报告中增加“AI 风险排序”列，并支持导出为工单系统导入格式 | 测试人员可以一键将最关键的漏洞提交至缺陷管理系统             |
| 自然语言规则生成（可选） | 允许用户用自然语言描述需求（如“允许用户输入直接拼接到 SQL 语句中应该被报告”），由 AI 辅助生成 Semgrep 或 CodeQL 规则 | 平台提供“AI 规则助手”对话框，调用 LLM 生成规则 YAML 并预览   | 生成规则在测试集上达到可用的准确率（>70%）                   |

**阶段三交付物**：
- 测试平台支持“深度审计模式”，可一键触发 CodeQL + AI 联合分析
- 扫描报告具备 AI 辅助判定、可利用性分析及修复建议
- 平台能够基于历史数据持续优化 AI 审计模型（反馈闭环）

## 跨阶段通用能力建设

| 能力项             | 实现方式                                                     |
| ------------------ | ------------------------------------------------------------ |
| 统一的扫描任务调度 | 采用 Celery / Temporal 等任务队列，支持异步、重试、超时控制  |
| 多仓库类型支持     | 支持 Git、SVN，以及主流 Git 服务（GitHub、GitLab、Gitee）的 API 拉取 |
| 增量扫描           | 针对 PR/MR，只扫描变更文件（SonarQube 的 PR 分析、Semgrep 的 `--baseline` 能力） |
| 安全凭证管理       | 集成平台的密钥管理模块，避免硬编码仓库 Token 或漏洞库 API Key |
| 合规与报告导出     | 支持生成 PDF/HTML 报告，并包含阶段一至阶段三的所有结果字段，符合企业内控要求 |

---

## 实施建议

- **迭代周期**：每个阶段建议 3~4 周（包含研发与测试），阶段一完成后即可获得可用的安全扫描能力。
- **平台开放 API**：所有扫描能力均应暴露 REST API，便于其他测试子系统（如性能测试、功能测试）调用或作为前置步骤。
- **用户文档**：每个阶段配套提供用户手册，包括如何配置扫描参数、编写自定义规则、解读 AI 审计结果等。

这份路线图将您原有的代码扫描思路与测试平台无缝结合，形成了从“基础能力”到“差异化壁垒”再到“智能深度防御”的完整演进路径。如果需要针对某一阶段的技术选型或 API 设计展开更细致的方案，我可以进一步提供。
