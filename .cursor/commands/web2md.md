# web2md：将 Markdown 中的远程图片本地化

把指定 `.md` 里引用的**网络图片**下载到 **`docs/.vuepress/public/images/`** 下的固定目录结构中，并把正文中的链接改为 **VuePress 静态资源路径**（以 `/images/` 开头），**不要**把图片放在与 `.md` 同级或同目录树下的资源文件夹（构建后站点无法按相对路径访问这些文件）。

## 使用方式

在对话中输入 **`/web2md`**，并在**同一条消息里**附上目标 Markdown 的**路径**（相对仓库根目录或绝对路径均可），例如：

`/web2md docs/某目录/文章.md`

若只给了文件名，先在仓库内解析出唯一路径或向用户确认。

---

## 资源目录规则（必须遵守）

设目标文件为 `docs/<子路径>/某文章.md`（即位于仓库的 `docs/` 之下）。

1. 令 `dir` = 该文件相对 `docs/` 的父目录路径（无父目录时为空）。
2. 令 `stem` = 文件名去掉 `.md` 后缀。
3. **图片保存目录**为：

   `docs/.vuepress/public/images/<dir>/<stem>/`

   其中 `<dir>` 为空时，路径为 `docs/.vuepress/public/images/<stem>/`（不要多出一层无意义目录）。

4. **Markdown 中的引用**一律写为站点根路径（与 `public/` 映射一致）：

   `/images/<dir>/<stem>/文件名.ext`

   `<dir>` 为空时为 `/images/<stem>/文件名.ext`。路径中的目录分隔符使用 `/`。

5. **CommonMark 链接目标不能含未转义空格**（VuePress 使用的 markdown-it 同样遵守）：**新建 `public/images` 下的目录名时不要使用空格**（例如用 `AgenticAI基础设施实践经验` 代替 `Agentic AI基础设施实践经验`），这样 `![alt](/images/...)` 无需 `%20` 也能正确解析。若因历史原因路径段中仍有空格，在括号内的 **URL 必须把空格写成 `%20`**，否则整段不会被识别为图片。

**示例**

- 文件：`docs/大模型/Agentic AI基础设施实践经验/专用沙盒环境的必要性与实践方案.md`（`docs` 下父级目录名可仍含空格）  
  保存到：`docs/.vuepress/public/images/AgenticAI基础设施实践经验/专用沙盒环境的必要性与实践方案/fig-01-architecture.png`（`public/images` 下建议用**无空格**目录名，与本仓库 Agentic 系列图一致）  
  文中：`![说明](/images/AgenticAI基础设施实践经验/专用沙盒环境的必要性与实践方案/fig-01-architecture.png)`

## 工作流程概要（供执行者遵循）

1. **定位文件**：读取用户给出的 Markdown 路径，确认文件存在且在 `docs/` 下（若不在 `docs/` 下，向用户说明本命令仅适用于站点文档树，或请其确认期望的 `public/images` 子路径）。
2. **收集图片 URL**：扫描正文中的图片引用，包括：
   - `![](https://...)`、`![alt](https://...)`
   - `[![alt](https://...)](https://...)`（整段为图片链接时按图片处理）
   - 仅处理明显为图片的 URL（路径或扩展名如 `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.svg` 等）；**不要**把普通文章超链接当成图片下载。
3. **创建资源目录**：按上文规则算出 `docs/.vuepress/public/images/<dir>/<stem>/`，若不存在则创建（`mkdir -p`）。
4. **命名与去重**：按**上下文**（邻近图注、章节标题、文中说明）为每个文件起有意义的英文名（建议 `kebab-case`）。下载前列出该资源目录下已有文件名，**新文件名不得与已有文件重名**；若冲突则加后缀区分（如 `-2`、`-section-1`）。
5. **下载**：用终端 `curl -fsSL -o "..." "URL"`（或等价方式）下载；失败时换 User-Agent 或报告错误，不要静默跳过。
6. **改写 Markdown**：将远程地址替换为 **`/images/<dir>/<stem>/文件名.ext`**（路径规则与第 3 步资源目录一致）。图片用标准 `![说明](/images/...)`；若 URL 中仍含空格则必须写成 `%20`（见上文第 5 条）。去掉仅用于打开原图的冗余外链包裹（若外层链接与内层图片 URL 相同）。
7. **自检**：文中不应再残留已迁移图片的远程 URL；`public/images/...` 下文件与正文中的 `/images/...` 引用一一对应。

## 约束

- 只改本次任务涉及的 Markdown 与新建/移动的图片；不做无关重构。
- 用户未提供路径时，说明用法并请其补充路径。
- **禁止**在与 `.md` 同级创建 `stem/` 文件夹存放供站点展示的图片；一律使用 `docs/.vuepress/public/images/`。

## 输出

完成后简短说明：使用的 `public/images` 子目录、下载了哪些图、替换了哪些引用。
